MCP의 참여자는 셋입니다. Claude Code나 VS Code 같은 AI 앱이 호스트이고, 호스트는 서버 하나당 클라이언트 하나를 만들어 전용 연결을 유지합니다. 서버는 컨텍스트를 제공하는 프로그램입니다. 내 컴퓨터에서 도는 로컬 서버는 표준 입출력, 즉 stdio로 통신하고, GitHub나 Sentry처럼 서비스가 호스팅하는 원격 서버는 Streamable HTTP(HyperText Transfer Protocol, 웹 통신 규약)를 씁니다. 서버가 내놓는 것은 세 가지입니다. 실행할 수 있는 도구, 읽을 수 있는 리소스, 재사용 프롬프트입니다. 이 가운데 에이전트가 가장 많이 쓰는 것이 도구입니다. 2026년 7월판 명세는 요청마다 필요한 정보를 담는 무상태 방식으로 바뀌었다는 점도 참고로만 짚어 둡니다.

Claude Code 문서 ‘MCP로 도구에 연결하기’. 이슈 트래커 기능 구현, 모니터링 분석, DB(데이터베이스) 질의 같은 MCP로 할 수 있는 일이 첫 절에 나온다.
$ claude mcp add --transport http notion \ https://mcp.notion.com/mcp $ claude mcp add --transport stdio airtable \ -- npx -y airtable-mcp-server $ claude mcp add --scope project ... ✓ project 범위는 .mcp.json에 저장
  • 범위: local(기본) · project(팀 공유) · user
  • project 서버는 처음 쓸 때 승인을 묻는다
연결은 claude mcp add 한 줄입니다. 원격 서버는 transport를 http로 주고 주소를 적고, 내 컴퓨터에서 실행하는 서버는 stdio로 두고 대시 두 개 뒤에 실행 명령을 적습니다. 공식 문서는 원격에는 HTTP를 권하고, SSE(Server-Sent Events, 서버 전송 이벤트) 방식은 더 이상 권하지 않는다고 합니다. 저장 범위는 local, project, user 세 가지입니다. project로 두면 저장소 루트의 .mcp.json에 들어가서 팀이 함께 쓸 수 있고, 보안을 위해 처음 쓸 때 승인을 묻습니다. 12교시 실습에서 여러분이 MCP 서버 하나를 직접 연결해 봅니다.

Invariant Labs 보안 공지(2025-04-01) ‘도구 오염 공격’. MCP의 심각한 취약점을 발견했고 Anthropic·OpenAI·Cursor 등이 영향권이라고 적었다.
도구 설명이 프롬프트에 그대로 들어가는 구조를 짚어, MCP 클라이언트의 검증 공백을 구체적 시연으로 보여 준다.
시연은 도구 설명을 검증·표시하지 않는 클라이언트가 대상이다. 확인창에는 단순한 도구 이름만 보였다.
도구 설명도 신뢰 경계 밖의 입력이다. 출처를 모르는 MCP 서버는 연결하지 않는다.
MCP 서버가 주는 도구 설명은 모델의 프롬프트에 그대로 들어갑니다. 2025년 4월 Invariant Labs는 이것을 악용한 도구 오염 공격을 공개했습니다. 겉보기에는 두 수를 더하는 도구인데, 설명 안에 숨은 지시가 있어서 모델이 사용자의 SSH(Secure Shell, 원격 접속 프로토콜) 키와 MCP 설정 파일을 읽어 도구 인자로 넘기게 만들었습니다. 사용자는 확인창에서 단순한 도구 이름만 봤습니다. 글은 도구 설명을 제대로 검증하거나 보여 주지 않는 모든 MCP 클라이언트에서 재현될 수 있다고 말합니다. 그래서 출처를 모르는 서버는 연결하지 않는 편이 낫습니다. 묶어 보면 장점은 위험을 구체적으로 시연했다는 것이고, 단점은 도구 설명을 검증하지 않는 클라이언트에 한정된 시연이라는 것입니다. 의미는 출처를 모르는 서버는 연결하지 않는 편이 낫다는 점입니다.

Claude Code 문서 ‘MCP 도구 검색으로 확장하기’. 도구 정의를 필요할 때까지 미뤄 세션 시작에는 도구 이름과 서버 지침만 싣는다.
시작에는 도구 이름·서버 지침만 싣고 필요할 때 정의를 불러와, 서버를 더 붙여도 창이 덜 찬다.
Claude Code 기준 기능이라 다른 도구는 방식이 다를 수 있다. 서버 지침이 부실하면 검색에서 잘 안 찾힌다.
앞 장의 창 낭비 문제에 대한 답. 도구 출력도 1만 토큰 초과 시 경고, 기본 상한 2.5만 토큰.
Claude Code 공식 문서에 따르면 도구 검색은 지금 기본값입니다. 세션을 시작할 때는 도구 이름과 서버 지침만 로드하고, 도구 정의는 클로드가 필요하다고 판단할 때 불러옵니다. 그래서 서버를 더 붙여도 창에 미치는 영향이 작다고 설명합니다. 환경 변수 ENABLE_TOOL_SEARCH로 끄거나, auto 뒤에 퍼센트를 붙여 도구 정의가 창의 그 비율을 넘을 때만 켜게 할 수도 있습니다. 도구가 돌려주는 출력도 별도로 제한합니다. 1만 토큰을 넘으면 경고하고 기본 상한은 2만 5천 토큰입니다. 서버를 만드는 쪽은 서버 지침을 잘 써야 검색에서 잘 찾힌다는 안내도 있습니다. 이 기능은 Claude Code 기준이고, 다른 도구는 방식이 다를 수 있습니다. 묶어 보면 장점은 서버를 늘려도 창이 덜 찬다는 것이고, 단점은 Claude Code 기준 기능이고 서버 지침이 부실하면 검색이 어렵다는 것입니다. 의미는 앞 장의 창 낭비 문제에 대한 답이라는 점입니다.

코드 파악은 언어 서버(LSP), 최신 API는 문서 조회

{{svg:p10-lsp-docs}}
언어 서버 프로토콜(LSP) 2016년 마이크로소프트가 낸 편집기 ↔ 언어 분석기 표준 규약. 정의로 이동, 참조 찾기, 이름 바꾸기, 오류 진단을 언어마다 같은 방식으로 묻는다. 대표 도구 Serena. Claude Code도 2025-12-19(2.0.74)에 LSP 도구를 넣었다(언어별 플러그인).
문서 조회 라이브러리 이름과 버전으로 공식 문서·예제를 검색해 필요한 부분만 창에 넣는다. 모델 지식의 날짜 한계를 메운다. 대표 도구 Context7. LSP가 아니라 문서 검색이다.
도구 이름보다 개념을 먼저 잡겠습니다. 에이전트가 코드를 이해하는 길은 두 가지입니다. 하나는 언어 서버 프로토콜, LSP입니다. 2016년 마이크로소프트가 VS Code와 함께 공개한 규약으로, 편집기가 언어별 분석기인 언어 서버에게 이 함수의 정의가 어디인지, 어디서 쓰이는지, 오류가 있는지를 같은 형식으로 묻습니다. 에이전트가 이것을 쓰면 문자열 검색 대신 심볼 단위로 정확히 찾고, 파일 전체를 읽지 않아 창을 아낍니다. 대표 도구가 Serena이고, Claude Code도 2025년 12월 19일 2.0.74 버전에서 LSP 도구를 넣어 언어별 플러그인으로 씁니다. 다른 하나는 문서 조회입니다. 모델의 지식은 날짜에서 멈춰 있으니, 라이브러리와 버전에 맞는 공식 문서를 찾아 필요한 부분만 넣어 줍니다. 대표 도구가 Context7입니다. 둘을 같은 종류로 묶어 말하면 안 됩니다. Context7은 LSP가 아니라 문서 검색입니다.

Context7: 버전에 맞는 문서만 가져오는 문서 조회

context7.com
공식 사이트 화면 캡처
Context7 첫 화면 ‘AI 에이전트를 위한 최신 문서’. 15만 3천 개 넘는 라이브러리 문서를 검색해 Claude·Codex·Cursor에 넣어 준다.
언제: 최신 프레임워크 API(Application Programming Interface, 프로그램 연동 규약)가 헷갈릴 때. 버전에 맞는 문서·예제만 가져온다. 연결: 원격 mcp.context7.com, 프롬프트에 use context7.
비용·위험: 무료 API 키(호출 한도 상향용). 라이브러리 문서는 커뮤니티 등록이라 README가 정확성·안전을 보장하지 않는다고 밝힌다.
모델 지식의 날짜 한계를 문서 조회로 메운다. MCP 외에 CLI(Command-Line Interface, 명령줄 도구)·스킬 방식도 있어 토큰 면에서 비교해 볼 만하다.
모델의 지식에는 날짜가 있어서, 최근에 바뀐 라이브러리 API(Application Programming Interface, 프로그램 연동 규약)를 옛 버전 기준으로 알려 주기도 합니다. Context7은 라이브러리 이름과 질문을 주면 해당 버전의 공식 문서와 예제를 찾아 그 부분만 가져옵니다. 도구는 두 개입니다. 라이브러리 이름을 식별자로 바꾸는 도구와, 그 식별자로 문서를 질의하는 도구입니다. 프롬프트 끝에 use context7을 적으면 쓰도록 유도할 수 있습니다. README는 MCP 방식과 별도로 CLI(Command-Line Interface, 명령줄 도구)와 스킬 방식도 지원한다고 설명합니다. 저장소의 첫 커밋은 2025년 3월 29일입니다. 묶어 보면 장점은 버전에 맞는 문서를 가져온다는 것이고, 비용·위험은 무료 API 키와 문서 정확성 비보장입니다. 의미는 모델 지식의 날짜 한계를 메운다는 점입니다.

Playwright MCP: 접근성 트리로 브라우저 조작

playwright.dev/docs/getting-started-mcp
공식 문서 화면 캡처 · 2026-10-28 확인

검색 결과가 걸러질수록 창에 들어오는 양도 준다. 가장 기본적인 토큰 절약.
$ rg "TODO" src/
ripgrep, rg는 정규식으로 디렉터리를 재귀 검색하는 도구입니다. README에 따르면 기본으로 gitignore 규칙을 따르고 숨김 파일과 바이너리 파일은 건너뜁니다. 에이전트에게 중요한 이유는 의미 없는 결과, 즉 node_modules나 빌드 산출물이 섞여 들어와 창을 낭비하는 것을 자연스럽게 막기 때문입니다. Claude Code 공식 문서는 검색과 파일 탐색에 내장 ripgrep을 쓰고, 이 바이너리가 시스템에서 안 돌면 시스템용 ripgrep을 따로 쓰라고 안내합니다. 설치는 각자 하시면 됩니다. 다른 도구가 grep을 rg로 바꿨는지는 1차 출처를 찾지 못해 말하지 않겠습니다. 묶어 보면 장점은 잡음 파일을 걸러 창을 아낀다는 것이고, 단점은 내장 바이너리가 안 돌면 별도 ripgrep이 필요하다는 것입니다. 의미는 검색 단계에서 이미 토큰 절약이 시작된다는 점입니다.
