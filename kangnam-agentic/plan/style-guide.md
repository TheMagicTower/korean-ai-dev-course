# 슬라이드 작성 규칙 (강사 승인 스타일, 2026-10-28)

기준 견본은 `src/periods/p01.html`입니다. 새 교시를 쓰기 전에 반드시 이 파일을 통째로 읽고 같은 마크업과 말투를 따릅니다.

## 형식
- 한 교시 = `src/periods/pNN.html` 한 파일. `<section class="slide" data-title="…">`의 나열. 문서 머리말·`<html>` 없음.
- 캔버스 1600×900. 한 장에 담을 양은 견본 수준(제목 1, 이미지 1, 요점 3개 안팎). 넘치면 장을 나눕니다.
- 모든 장 맨 위에 `.tag` 한 줄: `<b>날짜(YYYY-MM-DD)</b><span class="sep"></span>출처·사건 이름`. 날짜가 없는 개념 장은 `<b>개념 이름</b>`.
- 모든 장에 `<aside>` 발표자 노트. **합니다체**, 3~7문장, 슬라이드 글을 되풀이하지 말고 말로 풀어 설명. 강사가 그대로 읽을 수 있게.
- 슬라이드 본문은 짧은 명사형·단문. 노트는 완결된 문장.
- 장 끝의 이동 표시는 `<div class="next">→ N교시</div>`. 다른 교시와 연결될 때만.

## 이미지 (모든 장 필수)
1. **실제 화면 캡처 우선.** 공식 발표문·문서·저장소 README·논문 화면. `.frame` 안에 넣고 `.bar span`에 실제 주소를 적습니다. 아래 `.kind`에 "공식 문서 화면 캡처" 같은 종류와 날짜.
2. 캡처할 게 없으면 **직접 도식**: D2(`diagrams/src/pNN-이름.d2`) 또는 Pele(Mermaid 문법, `.mmd`). 본문에서 `{{svg:pNN-이름}}`로 넣습니다. Pele는 `<div class="diagram pele-theme">`로 감쌉니다.
3. 터미널 예시는 `.term`, 비교는 `.compare`, 표는 `.tbl`, 숫자는 `.stat`/`.stats`.
4. **AI 생성 이미지·일러스트 금지.** 실제 인물 사진 금지.
5. 표 하나만 있는 장(교시표 등)은 "직접 도식"으로 인정합니다. 남발하지 않습니다.

## 캡처 방법
- `NODE_PATH=$(npm root -g) node tools/capture.js pNN-이름 URL [CSS선택자] [순번] [--scroll=PX] [--clip=x,y,w,h] [--width=1600 --height=1000]`
  → `assets/captures/pNN-이름.jpg`. 파일 이름 앞에 반드시 자기 교시 번호(`pNN-`)를 붙입니다(병렬 작업 충돌 방지).
- 캡처 후 반드시 Read로 이미지를 열어 쿠키 배너·로그인 벽·빈 화면이 아닌지 확인합니다. 쿠키 배너가 있으면 `--scroll`이나 `--clip`으로 피하거나 요소 선택자로 찍습니다.
- 차단된 곳: x.com(로그인 벽), openai.com(Cloudflare), kroki.io, jsdelivr. 이런 곳은 다른 공식 출처나 직접 도식으로 대체하고, `plan/capture-todo.md`에 "강사 브라우저로 캡처 필요" 줄을 추가합니다.
- 이미 있는 캡처(`assets/captures/`)는 그대로 재사용해도 됩니다. 1교시 견본에 쓴 것들입니다.
- 이미지가 강사 본인의 실제 작업 화면이어야 하는 장(코디네이터 실행 화면, 이슈 원장 화면, 페르소나 평가 실행 등)은 직접 도식으로 만들고 `.kind`에 "강사 실제 화면으로 교체 예정"이라고 쓴 뒤 capture-todo에 적습니다.

## D2 도식 규칙
- 파일 끝에 다음 두 줄을 꼭 둡니다(글자 크기):
  ```
  **.style.font-size: 26
  (** -> **)[*].style.font-size: 22
  ```
- 강조할 상자는 `style.stroke: "#ff00ff"` (렌더러가 강조색으로 바꿉니다). 색을 직접 지정하지 않습니다.
- 가로 16:9 공간에 맞게 `direction: right`를 기본으로. 상자 10개 안팎.
- 렌더: `node tools/diagrams.mjs pNN-이름` (tools 폴더 아님, 프로젝트 루트에서).

## 사실 확인
- 날짜·수치·인용은 1차 출처(공식 블로그, CHANGELOG, 문서, 논문, 저장소)로 확인한 것만. `plan/research-timeline.md`의 검증한 연표와 "서사와 사실이 다른 곳"을 우선 따릅니다.
- 강사 서사와 사실이 다르면 사실을 쓰되 서사의 흐름은 살립니다(예: Claude Code는 터미널 에이전트의 '시초'가 아니라 '주류로 만든 도구').
- 인용은 영어 원문 15단어 이하, 한 장에 하나.
- 확인 못 한 주장은 쓰지 않습니다(예: Trae의 grep→rg 교체).

## 말투와 용어
- 강사 1인칭은 노트에서 "저는", "제가". 강사 운영 방식은 tag에 "강사 운영 방식"으로 표시.
- 용어: 에이전트, 하네스, 스킬, 서브에이전트, 워크트리, 컨텍스트 창, 압축, 자동 승인, 이슈 원장, 머지 큐, 스모크 테스트, 페르소나 평가, 코디네이터-배치 패턴.
- 학생은 SW 3~4학년. 도구는 자유(Claude Code, Codex CLI, Gemini CLI, Cursor 등). 특정 도구만 정답처럼 말하지 않습니다.

## 교시 구성 패턴 (강의 교시, 60분 ≈ 18~26장)
1. 표지 장(`.section-slide`): "N회차 · N교시", 제목, 이 교시에 볼 실제 화면 strip 4장.
2. 지난 교시와의 연결 1장(앞 단계의 문제).
3. 본문 블록들(구성안 표의 블록마다 2~4장).
4. 확인 질문 1장(질문 2~3개, 이미지 포함).
5. 정리 + 다음 교시 예고 1장.

## 실습 교시 (4·8·12·16교시, 10~16장)
- 목표, 준비물, 단계별 실습(각 단계에 실제 명령/설정 예시 `.term`), 확인 방법, 과제 안내(제출물·기한·평가 기준), 막힐 때.
- 누적 과제는 "나만의 하네스 만들기". 코드형(Agent SDK·직접 짠 루프)과 설정형(Claude Code·Codex 등 위에 규칙·훅·스킬·MCP·권한·루프 조합) 두 트랙 모두 허용.

## 빌드·검사
```
python3 tools/build.py pNN                      # preview/pNN.html (자기 교시만)
NODE_PATH=$(npm root -g) node tools/qa.js pNN   # qa/pNN/sXX.png, qa/pNN-sheet-K.png, 넘침·이미지 누락 보고
```
- qa가 "no overflow"를 내고, 콘택트 시트를 Read로 직접 보고 글자 겹침·빈 화면·작은 도식이 없을 때 완료입니다.
- 공용 파일(src/deck.css, src/deck.js, tools/*, 다른 교시 파일)은 고치지 않습니다. 필요한 스타일이 없으면 인라인 `style=""`로 최소한만.
