# 작업 인계

한국어 존댓말로 설명하며 코드·API 식별자는 원문을 유지합니다.

## 적용 범위와 비용

사용자의 명시적 요청과 기존 프로젝트 규칙을 먼저 따릅니다. 사용 범위(개인·팀·외부), 목표 단계(PoC·MVP·운영), 실제 위험, 이번 작업 예산과 완료 조건을 기존 계약에서 읽습니다. 없으면 작업에 영향을 주는 부분만 확인하거나 가정을 표시합니다. 저위험 개인 작업에 기업용 문서·로그인·CI/CD·독립 리뷰를 일괄 추가하지 않습니다. 필요한 조건을 통과하면 종료하고 선택 개선은 후속으로 남깁니다. 예산 소진 시 필수 미달은 미완료로 인계합니다. 없는 도구·권한·실행 증거를 가정하지 않습니다.

## 수행

1. 종료 시에는 전체 대화 대신 다음 실행에 필요한 실제 상태를 정리합니다. 재개 시에는 인계만 믿지 말고 현재 파일·브랜치·버전·실행 결과의 변화를 먼저 확인합니다.
2. 프로젝트 수준·목표·현재 마일스톤/스테이지/스프린트/Task·이슈·워크트리·진행 단계를 연결합니다. 작은 프로젝트는 필요한 계층만 씁니다.
3. 유지할 ADR·Spec·선택 시안, 이미 통과한 검토와 다시 열어야 할 조건을 남깁니다. 새 세션이 이미 끝낸 설계·리뷰를 이유 없이 반복하지 않게 합니다.
4. 완료 증거·남은 필수·선택 후속·오류 재현·미확인·사용자 판단 요청을 나눕니다. 계획을 완료 사실로 기록하지 않습니다.
5. 남은 시간·비용·재시도 한도, 다음 행동과 종료 조건을 명시합니다. 측정하지 않은 토큰을 만들어 내지 않습니다.
6. 분리된 자동 프로세스에서는 이슈/실행 ID·기준 커밋·단계·산출물·판정·재개 조건을 남깁니다. 작업 소유권·상태 전이·스케줄을 이미 구현했다고 가정하지 않습니다.

## 인계 형식

```text
상태·목표·사용 범위/단계:
현재 경로·브랜치·버전·작업 계층:
유지할 결정·Spec·시안:
완료한 것과 실행 증거:
이미 통과한 검토·재검토 조건:
남은 필수·선택 후속·실패 재현:
필요한 사용자 결정·재개 조건:
남은 예산·다음 행동·종료 조건:
```

위 기록과 실제 상태가 일치하면 인계를 종료합니다. 실제 비밀값·개인정보·불필요한 로그 전체를 복사하지 않습니다.
