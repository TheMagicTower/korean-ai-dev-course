발표 규칙발표 5분 · 질의 2분 · 엄수

5분 발표 중 가장 오래 말할 곳은 실행 기록과 실패입니다

{{svg:p17-slot}}

가장 오래 말할 곳은 실행 기록과 실패입니다. 구조도는 읽어 주지 말고 흐름만 짚습니다.

5분은 짧습니다. 구조도는 한 장 보여 주고 일 분 반 안에 흐름만 말합니다. 트랙 선택은 코드형인지 설정형인지 한마디면 됩니다. 시간을 가장 많이 쓸 곳은 같은 기준 과제의 실행 기록과 실패입니다. 청중이 가장 궁금해하는 것도, 비교가 되는 것도 여기입니다. 마지막 한 줄 정리 뒤에 2분 동안 질의를 받습니다. 타이머는 제가 화면에 띄웁니다.

모두 같은 과제를 돌리므로, 차이는 내 하네스에서 나옵니다

발표를 서로 비교할 수 있도록 모두 같은 기준 과제를 돌립니다. 시작 저장소와 과제 문장이 같기 때문에 결과의 차이는 하네스에서 나옵니다. 화면의 과제 문장은 예시이고, 실제 문장과 시작 저장소는 공지한 것을 씁니다. 과제를 고쳐서 돌리면 비교가 안 되므로 그대로 돌립니다. 몇 번 돌려도 좋지만 발표에는 대표 한 번의 기록과 횟수를 함께 적어 주세요.
평가 기준발표 평가 100점 + 동료 평가

점수는 성공 여부가 아니라 기록의 정직함에 줍니다

{{svg:p17-rubric}}

구조·설계 25, 실행 기록 25, 점검 장치 20, 실패 분석 20, 발표 10점(합계 100점). 실패해도 감점하지 않습니다.

평가는 발표 평가 100점과 동료 평가로 나뉩니다. 발표 평가는 16교시 최종 과제 평가 기준과 같습니다. 구조·설계 25점, 실행 기록 25점, 점검 장치 20점, 실패 분석 20점, 발표 10점입니다. 과제가 성공했는지보다 기록이 정직한지, 실패의 원인과 고친 장치가 연결되는지를 봅니다. 동료 평가는 발표마다 이해했다, 믿을 만하다, 써 보고 싶다 세 항목을 1점에서 5점으로 입력하고 질문을 하나 남깁니다. 점수 배분은 안내한 기준이고, 확정되면 공지한 것을 따릅니다.

발표 템플릿은 다섯 장입니다

{{svg:p17-template-map}}

다음 네 장이 각 장의 빈칸 양식입니다. 그대로 복사해 채우면 됩니다.

템플릿은 다섯 장입니다. 하네스 구조도, 트랙, 기준 과제 실행 기록, 실패한 것, 배운 것입니다. 마지막 두 장은 한 장으로 합쳐도 됩니다. 장 수가 정해져 있으니 꾸미는 데 시간을 쓰기보다 내용을 채우는 쪽이 좋습니다. 다음 장부터 한 장씩 빈칸 양식을 보여 드립니다.
템플릿 장 1하네스 구조도

장 1 · 상자 이름을 내 하네스의 실제 이름으로 바꿉니다

{{svg:p17-harness-arch}}

상자 이름을 내 하네스의 실제 이름으로 바꿉니다. 없는 장치는 지우고, 직접 추가한 장치는 넣습니다.

첫 장은 구조도입니다. 화면은 양식이고 상자 이름은 바꿔도 됩니다. 목표와 완료 조건이 들어가고, 하네스가 워커를 돌리고, 규칙과 스킬이 워커를 붙들고, 테스트와 스모크로 점검하고, 기록이 남는 흐름입니다. 사용하지 않은 상자는 과감히 지웁니다. 여러분이 직접 만든 장치가 있다면 그것이 구조도의 주인공입니다. 발표에서는 일 분 반 안에 화살표를 따라가며 한 번만 설명합니다.
템플릿 장 2트랙 선택: 코드형 · 설정형

장 2 · 코드형과 설정형은 장단점이 다르고, 평가는 같은 기준입니다

코드형 · Agent SDK 등으로 직접 짠 루프
  • 장점: 도구 호출과 종료 조건을 코드로 정확히 통제
  • 단점: 루프·도구 표를 직접 구현해야 해 손이 많이 간다
  • 고르는 때: 통제 지점을 코드로 보여 주고 싶을 때
설정형 · Claude Code·Codex 위에 조합
  • 장점: 규칙·훅·스킬·MCP·권한을 설정으로 빠르게 조합
  • 단점: 동작은 도구가 정한 틀 안에서만 바꿀 수 있다
  • 고르는 때: 기존 도구 위에서 빠르게 쌓아 보고 싶을 때

→ 어느 쪽이 더 낫다는 평가는 없습니다. 구조도와 같은 과제의 실행 기록을 내면 같은 기준으로 평가합니다.

두 번째 장은 트랙 표시입니다. 코드형은 Agent SDK나 직접 짠 루프로 도구 호출과 종료 조건을 코드로 통제한 경우입니다. 장점은 통제가 정확하다는 것이고, 단점은 루프와 도구 표를 직접 구현해야 한다는 것입니다. 설정형은 Claude Code나 Codex 같은 도구 위에 규칙, 훅, 스킬, MCP, 권한, 루프를 조합한 경우입니다. 장점은 빠르게 쌓을 수 있다는 것이고, 단점은 도구가 정한 틀 안에서만 바꿀 수 있다는 것입니다. 어느 트랙이 더 낫다는 평가는 없습니다. 다만 어떤 이유로 이 트랙을 골랐는지 한 문장을 적어 주세요. 이 장은 30초면 충분합니다.
템플릿 장 3기준 과제 실행 기록: 토큰 · 시간 · 성공 여부

장 3 · 토큰·시간·결과를 표 한 줄로 적습니다

{{svg:p17-runlog}}
| 항목 | 값 | 토큰 합계 ___ 소요 시간 ___ 분 실행 횟수 ___ 회 결과 성공 / 부분 / 실패
  • 토큰(AI가 처리한 글자 단위)은 도구가 보여 주는 값 그대로
  • 못 잰 항목은 “못 쟀다”고 적는다
가장 중요한 장입니다. 토큰, 시간, 성공 여부를 표 한 줄로 적습니다. 토큰은 사용하는 도구가 보여 주는 값을 그대로 옮기고, 추정하지 않습니다. 재지 못한 항목은 비워 두지 말고 못 쟀다고 적어 주세요. 그것도 하나의 기록입니다. 성공 판정은 과제 문장의 완료 조건을 통과했는지로 합니다. 여러 번 돌렸다면 횟수를 함께 적습니다.
템플릿 장 4·5실패한 것 · 배운 것

장 4·5 · 실패는 하나만 골라 네 칸을 채웁니다

{{svg:p17-lessons}}

실패는 하나만 골라 이 네 칸을 채웁니다. 여러 개를 나열하지 않습니다.

마지막 장은 실패입니다. 가장 아쉬웠던 실패 하나를 골라 무엇이 실패했는지, 왜 그랬는지, 어떤 장치로 고쳤는지, 다음에 먼저 할 일이 무엇인지를 한 줄씩 적습니다. 고치지 못했다면 고치지 못했다고 쓰고 다음 일만 적어도 됩니다. 이 과정에서 계속 본 것처럼, 장치는 앞 단계의 실패에서 나왔습니다. 여러분의 실패가 하네스를 한 단계 키운 근거가 됩니다.
