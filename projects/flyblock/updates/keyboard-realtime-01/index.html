# 키보드·실시간 업데이트 — 진단과 실행 계획

기존 문제: 열·방향 드롭다운 → 확정 버튼 → 양측 동시 한 라운드가 진행되었습니다. 낙하 중 움직임·키보드·독립적인 상대 진행이 없었습니다.

승인된 변경: 두 보드가 50ms 고정 틱으로 독립 진행하고, 500ms마다 현재 블록이 한 칸 떨어집니다. 사람은 ←/→ 이동, ↑ 회전, ↓ 한 칸 빠르게, Space 즉시 낙하, P 일시정지/재개를 사용합니다. 터치 버튼도 제공합니다. 시작 전에는 시간이 흐르지 않습니다.

변경 계약:
- 새 `realtime.js`는 기존 순수 라운드 엔진의 제거·방해 블록 규칙을 재사용합니다. 현재 움직이는 블록의 충돌·회전·경로·독립 잠금·공격 대기열·종료를 담당합니다.
- 두 칸은 낙하 중 함께 움직이고 잠길 때 각 열의 중력을 적용합니다. 벽 회전은 좌우 한 칸 보정만 허용하며 천장 위 회전은 거부합니다.
- 상대는 같은 실제 12뉴런/13연결 모델이 **도달 가능한 수** 중 목표를 선택하며, 화면에서 150ms마다 해당 경로를 한 단계씩 실행합니다. 공간이 없어지면 실제 회로로 다시 판단합니다. 실패하면 전체 경기를 중지합니다.
- 공격은 즉시 상대 대기열에 넣고 상대 블록이 다음 잠금에 도달할 때 반영합니다. 같은 틱의 공격은 모아 동시에 전달합니다. 진행 중인 블록과 겹치는 방해 블록 삽입을 피하기 위한 명시적 단순화입니다.
- 중앙 생성 위치가 막히거나 방해 블록이 넘치면 패배, 같은 틱 양쪽 패배는 무승부입니다. 활성 플레이 120초에는 제거한 색 블록 수로 판정합니다.
- 키보드는 포커스된 게임 영역에서만 동작합니다. 입력 필드·수정키 조합을 무시합니다. Space/회전/P 자동 반복은 추가 동작을 만들지 않습니다. 포커스 이탈·창 전환·페이지 숨김에는 일시정지하며 자동으로 재개하지 않습니다.
- 리플레이에는 틱별 사람 입력·시드·런타임/모델 버전·최종 틱을 저장합니다. 일시정지 구간에는 시뮬레이션 틱이 없고, 재생은 활성 플레이 시간으로 진행합니다. 이전 라운드 로그와 호환된다고 표시하지 않습니다.
- 기존 `evidence/` 로그·스크린샷·40경기 기준선은 동결합니다. 기준선은 구 라운드 방식 결과임을 명시합니다.

작업 순서: 순수 런타임과 입력/시계 어댑터 → 단위/회귀 시험 → 작은 헤더와 보드 중심 UI → 입력/재생/중단 자체 검토 → 메인 에이전트 브라우저 검증.

증거는 이 폴더의 `prompt.txt`, `events.jsonl`, `tests.txt`, `response.md`에 기록합니다. 최초 구현 기록을 덮어쓰지 않습니다. 실제 브라우저 검증과 공개 배포 시각은 메인 에이전트가 별도로 기록합니다.

- `controller.js`: 원본 연결과 계산 방식은 유지하고 도달 가능한 후보 수 필터를 선택 인자로 추가했습니다.
- `app.js`, `index.html`, `style.css`: 작은 헤더, 보드 중심 화면, 키보드/터치, 포커스 이탈 일시정지, 리플레이 연결입니다.
