### 6교시 · TDD와 DDD: 범위를 묶는 삼중 방어 (단계 7, 7-1)
- 스펙 → 실패하는 테스트 → 구현 → 통과. 사람은 분량 때문에 못 하던 TDD를 AI에게.
- 에이전트가 테스트를 속이는 문제: 테스트 수정·삭제, 하드코딩, skip. 대응: 테스트 파일 보호(권한 deny·훅), 테스트 먼저 커밋, 리뷰어 서브에이전트. (Anthropic Claude Code best practices의 TDD 권고 확인)
- DDD 기초: 유비쿼터스 언어, 바운디드 컨텍스트, 엔티티·값 객체를 아주 짧게. 왜 에이전트에게 필요한가: 볼 범위 축소.
- 프롬프트에 수준 명시: PoC·MVP vs 엔터프라이즈(클린 아키텍처: 도메인/응용/인프라 의존 방향). 같은 요구사항을 두 수준으로 시킨 결과 비교(파일 수·줄 수).
- 강사 자료: `plan/instructor/domain-testing.md`(도메인 테스트).
- 중간 질문 시간 5분, 정리.

### 14교시 · SDD 이후: ADR과 이슈 원장 (단계 18, 18-1)
- SDD의 한계: 길어지고 낡는 스펙, 에이전트는 낡은 스펙도 믿는다, 병렬 작업에서 단일 스펙 충돌.
