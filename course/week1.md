# 1주차 · 문제를 정하고 첫 결과를 봅니다

오늘의 산출물은 **짧은 프로젝트 계약과 실행 가능한 시작점**입니다. 완성 목표를 작게 정할수록 4주 뒤 실제로 사용할 가능성이 높아집니다.

## 120분 진행표

| 시간 | 활동 | 결과 |
|---|---|---|
| 0–10 | 목적과 완료 수준 | 개인·MVP·운영 차이 |

## 개념 1 — 사용자는 누구이며 무엇을 얻습니까?

‘AI로 앱을 만든다’는 구현 방식입니다. 목표는 ‘퇴근 전 미처리 문의를 찾아 다음 담당자에게 넘긴다’처럼 사용자 행동과 결과로 적습니다. 비즈니스 레이어에는 업무 규칙·책임·예외를, 사용성 레이어에는 숙련도·빈도·실수와 회복을 적습니다.

필수 기능은 수업 계약에서 최대 세 개로 좁힙니다. 이 수는 모든 개발의 영구 규칙이 아닙니다. 어떤 입력이 들어오고 어떤 결과가 유지되어야 하는지 한 줄로 설명해 보세요.

## 개념 2 — 모델과 에이전트는 다른 선택입니다

| 요소 | 역할 | 확인할 질문 |
|---|---|---|
| 모델 | 판단·코드·설명 생성 | 이 작업에 충분한가? |
| 프로바이더 | 모델 접근·과금·운영 | 내 계정에서 사용 가능한가? |
| 에이전트 | 파일·터미널·도구 실행과 작업 반복 | 필요한 도구·권한이 있는가? |
| 사고 수준 | 작업에 투입하는 추론 설정 | 시간이 더 필요한 문제인가? |
| 스킬 | 필요할 때 읽는 수행 지침 | 지금 단계와 맞는가? |

높은 사고 수준이 모든 작업에서 더 좋은 선택은 아닙니다. 단순 수정은 충분한 조합으로 시작하고, 해결되지 않은 복잡한 원인 분석에 더 강한 조합을 사용합니다. 같은 ‘high’ 이름도 모델마다 동일한 계산량을 뜻하지 않습니다.

Claude·GPT의 디자인 결과는 모델 버전·참조·요구·도구에 영향을 받습니다. UI 코드를 만드는 것, 이미지를 이해하는 것, 실제 이미지 파일을 생성하는 것은 구분합니다. Claude 디자인은 이 과정의 기본 시연 사례이며 다른 도구로 실습할 수도 있습니다.

Astra는 범용 작업 모델의 사례, Jev는 정해진 선택·점수 판단의 사례로 비교합니다. AGI나 최신 벤치마크 주장만으로 작업을 맡기지 않습니다. 자세한 공식 출처와 한계는 모델 부록에 있습니다.

## 강사 시연 — 화면 비교는 어떻게 합니까?

같은 ‘문의 목록’ 요구와 시작 상태를 두 조합에 제공합니다. 사용자·정보·화면 폭·시간 한도를 같게 하고, 문의 식별·처리 행동·한국어 가독성 세 조건을 비교합니다. 시연 결과를 미리 승자로 정하지 않습니다. 실행하지 못한 도구는 ‘미실측’으로 기록합니다.

```text
문의 담당자 한 명이 데스크톱에서 사용할 문의 목록 목업을 만들어 주세요. 문의 제목·상태·작성일이 보이고 처리 완료로 바꿀 수 있어야 합니다. 임시 데이터 사용을 표시하고, 지금은 로그인·실제 API·DB 구현을 제외합니다. 핵심 화면 하나로 제한하고 어떤 부분이 목업인지 설명해 주세요.
```

## 이어지는 서비스 사례 — 사용자와 범위를 정합니다

취업 준비생 지민은 여러 곳에 흩어진 지원 공고를 찾느라 시간을 씁니다. 첫 버전은 공고 저장·상태 변경·조회로 제한합니다. 개인 검증용이면 로컬 저장으로 시작할 수 있지만 친구도 쓰는 MVP라면 계정별 데이터 분리가 필수입니다. 목업과 함께 가장 불확실한 기술 동작 하나를 검증합니다.

**직접 해보기:** 사용 범위·제품 단계·필수 절차·생략 이유를 한 줄씩 적어 보세요.

## 내 프로젝트 실습

```text
프로젝트 시작 스킬을 사용해 [대상 사용자]가 [문제]를 해결하는 도구의 계약을 작성해 주세요. 사용 범위는 [개인/팀], 목표는 [개인 완성품/MVP]입니다. 핵심 흐름은 [입력→행동→결과]이며 필수 기능은 최대 세 개로 좁혀 주세요. 적정 사용 난이도·접근 경계·대표 실패·대체재와 직접 만들 이유를 확인하고 사실과 가정을 나눠 주세요. 아직 상세 DB는 확정하지 마세요.
```

계약이 정리되면 스킬 인식을 확인하고 첫 화면 또는 최소 입출력을 실행합니다. 화면 없는 자동화는 샘플 입력과 결과 파일로 시작합니다. 사용자 자료를 무단으로 외부 모델에 보내지 말고 실습용 샘플을 사용합니다.

## 오늘의 완료 확인

- [ ] 사용자 문제와 핵심 흐름을 한 문장으로 설명했습니다.
- [ ] 사용 수준·실제 위험·포함/제외·예산을 기록했습니다.
- [ ] 주력 도구·모델·사고 수준을 선택했습니다.
- [ ] 첫 실행 결과와 실제로 읽은 스킬을 확인했습니다.
- [ ] 다음 세션의 목표·현재 상태·미확인을 인계했습니다.

막혔다면 설치·계정 문제와 코드 문제를 분리합니다. 첫 실행이 안 되는 상태에서 기능을 늘리지 않습니다. 수업 밖 고도화는 선택이며 필수 완성 범위는 수업 안에 맞춥니다.
