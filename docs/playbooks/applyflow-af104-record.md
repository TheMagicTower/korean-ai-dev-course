# AF-104 실제 수행 기록 — 저장한 공고 검색

2026-09-23 · [실행 매뉴얼](applyflow-runbook.md) · [실행 예제](https://themagictower.github.io/korean-ai-dev-course/course/examples/applyflow/)

이 기록은 실제 코드 변경과 실행 결과입니다. 매뉴얼의 복사용 프롬프트는 교육용으로 재구성했으며 실제 대화 로그로 표시하지 않습니다. AF-104는 내부 식별자이고 발급된 GitHub 이슈 번호가 아닙니다.

## 1. 시작점과 작업 계약

기준 커밋: `f02343aba695432bce8a539e8d2e49205bc300ed`. 기존에는 공고 저장·상태 변경·상태 필터·브라우저 저장이 있었고 회사·직무 검색은 없었습니다.

**요청:** 저장한 공고를 회사 이름 또는 직무 일부로 찾고, 선택한 상태에 해당하는 결과만 봅니다.

**완료 조건:** 공백 정리·영문 대소문자 무시·부분 검색·상태 AND 결합·빈 검색·빈 결과·검색 지우기·저장 데이터 불변. 인증·외부 공고 검색·서버 저장은 제외했습니다.

**계획:** 검색 순수 함수와 계약 검사 → UI 입력/지우기 → 기존 목록 연결 → 모델 검사와 브라우저 검증. [작성한 계획](../plans/applyflow-runbook.md)을 참고하세요.

## 2. 실제 실행 순서

| 단계 | 수행 | 근거와 판정 |
|---|---|---|
| 온보딩 | 기존 README·모델·화면 연결·검사·Git 상태 확인 | 기존 변경 없는 기준 버전에서 시작 |
| 스펙·계획 | 작은 검색 기능으로 범위 한정 | 저장 형식과 인증을 변경할 필요 없음 |
| 실패 확인 | `selectJobs` 계약 검사 추가 후 실행 | `TypeError: m.selectJobs is not a function`, 종료 코드1 |
| 구현 | 검색 함수·입력·지우기·목록 연결 | 아래 변경 파일과 계약 연결 |
| 자동 검증 | 기존 모델 검사 + 새 검색 계약 검사 | 모두 통과, 종료 코드0 |
| UI 검증 | 회사/직무 검색·상태 결합·빈 결과·지우기·재실행 | 아래 브라우저 관찰 |
| 검토·인계 | 계약·변경·증거 비교 | 이번 Task 범위의 로컬 검증 통과. 공개 전달은 배포 버전을 별도 확인 |

실패는 검색 함수를 구현하기 전에 확인했습니다. 테스트가 처음부터 통과했다고 소급해 기록하지 않았습니다. Node 버전은 `v22.23.1`입니다.

## 4. 자동 검사 결과

저장소 루트에서 실행합니다.

```bash
node course/examples/applyflow/test-model.cjs
```

실제 출력:

```text
PASS: trim, persistence, states, blank input, unknown id/status, duplicate, corrupt storage preservation, save failure
PASS AF-104: company/role, case, trimming, status AND, empty query/results, data unchanged
```

기존 입력·저장·상태 계약과 새 검색 계약을 함께 검사했습니다. 영문 `LightLab`에 ` lightLAB `를 입력하는 경우, 직무에 `개발자`를 입력하는 경우, 상태와 검색의 교차, 빈 결과, 빈 검색, 원본 배열의 JSON 불변을 확인했습니다. `git diff --check`도 통과했습니다.

## 5. 브라우저에서 확인한 사용자 흐름

로컬 `http://localhost:8765/course/examples/applyflow/`에서 기존 가상 공고4개를 사용했습니다. 테스트 전후 화면 총수는4개였고 진행 중은3개였습니다.

| 행동 | 관찰한 결과 |
|---|---|
| 전체 상태에서 `  라이트랩  ` 검색 | ‘라이트랩 (가상)’ 한 건 표시 |
| `개발자` + 면접 상태 | ‘교육 테스트 회사 / 프론트엔드 개발자’ 한 건 표시 |
| `존재하지않는공고` 검색 | 검색어와 상태를 바꾸라는 빈 결과 안내 |
| 검색 지우기 | 면접 선택 유지, 면접 공고2개 표시 |
| 검색어 입력 후 새로고침 | 검색어 초기화·전체 상태, 기존4개와 각 지원 상태 유지 |
| 390px 모바일 | 문서 폭390px, 검색 행 폭308px, 가로 넘침 없음 |
| 브라우저 오류 확인 | 해당 검증 세션 오류 로그 없음 |

이 검증은 샘플 화면과 로컬 모델 동작에 대한 증거입니다. 모든 브라우저·기기·접근성 보조 도구를 검증한 것은 아닙니다. JSON 백업 다운로드 내용은 이번 검색 작업에서 별도 재검증하지 않았습니다.

## 6. Jev 분류와 상태 판단의 경계

계정 환경변수 `TYPESAFE_API_KEY`가 설정되어 있음을 값 출력 없이 확인했습니다. 초기 호출은 HTTP403이었지만, 공식 Bearer 인증으로 curl 호출한 결과 HTTP200이었습니다. 반환 모델은 `jev-1.13.0`입니다.

| 질문 | 실제 Jev 결과 | 처리 |
|---|---|---|
| 문서 링크·작업 식별자의 기계적 점검 | simple, confidence1.00 | GPT-5.6 Luna max에 읽기 전용 위임 |
| 매뉴얼 설계·구현 검증 | complex, confidence1.00 | 주 에이전트 수행 |

사용량은 입력436·출력60토큰입니다. 호출의 키 값은 문서에 포함하지 않았습니다. [공식 호출 규격](https://docs.typesafe.ai/introduction/quickstart)을 따랐으며 403의 원인을 키 누락으로 확정하지 않았습니다.

**상태 판단:** 주 에이전트가 계약과 실제 검사 근거를 비교해 ‘통합·전달 대기’로 판단했습니다. Jev가 AF-104 상태 전이를 자동 판정하거나 실행기가 머지한 사례는 아닙니다. 배포 후보가 바뀌면 관련 검사를 다시 확인합니다.
