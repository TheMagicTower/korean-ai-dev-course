
### 13교시 · 에이전트 팩토리, 병렬 에이전트 관리(Orca), 코디네이터-배치 패턴 (27장, 60분)

**주의 (흔한 오해)**
- Orca 첫 커밋 날짜(2026-03-16)는 강사 정리 연표 기준. 별 약 10만 8천은 공식 사이트 상단 표시. 화면은 “다음 달에는 다를 수 있다”(릴리스 하루 한 번 수준, 17장).
- Orca는 새 실행 기본값으로 각 에이전트의 권한 우회 플래그를 채워 둔다. 워크트리는 파일 격리일 뿐 에이전트는 접근 가능한 파일·네트워크를 그대로 쓴다. 수동 승인 설정 확인을 당부(17장).
- Codex 앱은 월(2026-02 초)만 확인했고 OpenAI 사이트 차단으로 2차 보도+현재 문서 기준(7장). 가격은 계속 바뀌므로 격차 사실만(3장).
- agent teams는 연구 프리뷰, 토큰 많이 쓰고 환경 변수를 켜야 함. 팀원은 직접 메시지, 권장 3~5명, 같은 파일 수정 시 덮어씀(8장).
- `/loop`의 첫 도입은 2026-03-06이고 간격 생략 모드가 나중에 상시 제공. 정확한 도입 시점은 특정 못 해 “4월 무렵 이후”로만 말한다. 세션이 열려 있어야 돌고 7일 후 스스로 사라짐(21장).
- 23장은 예시 도식, 24장은 모형이며 실제 화면이 아니다(슬라이드에 ‘강사 실제 화면으로 교체 예정’으로 표기, 일수·배치 크기는 가상 값).

**예상 질문**
- “꼭 Orca를 써야 하나요?” → 아니오. 터미널 분할+`git worktree`로 같은 흐름.
- “코디네이터가 코딩하면 안 되는 이유?” → 창이 코드·로그로 차서 압축이 반복되고 목표를 잊는다.
- “병렬이면 항상 빨라요?” → 같은 파일을 건드리면 합치는 비용으로 이득이 사라진다. 병렬 실행은 쉽고 나눠 주고 점검하는 일이 어렵다.

**시연·준비**
- Orca 세 에이전트 경주 데모 또는 터미널 분할+워크트리 대체 시연(15장). 코디네이터 프롬프트(`/loop`+목표 문서) 시연 준비(24장 모형과 같은 흐름).
- 23·24장은 강사 Claude Code 코디네이터 실행 화면 캡처 대기(`/loop` 깨우기 한 장면: gh 상태 읽기·다음 배치·다음 깨우기 시각, 며칠 실행 기록. plan/capture-todo.md, 13교시 2건).

### 14교시 · SDD 이후: ADR과 이슈 원장 (28장, 60분)
목표: 큰 스펙 하나의 세 가지 문제를 알고, ADR(Architecture Decision Record, 아키텍처 결정 기록)(특히 ‘다시 판단할 조건’)과 이슈 원장을 에이전트 운영에 쓰는 법을 설명하게 한다.

| SDD의 세 문제 | 3–6 | 9 | 길어지고 낡음(Nygard 2011), 에이전트는 낡은 스펙도 믿음, 병렬에서 한 스펙 충돌. 스펙을 없애지 않고 성격별로 쪼갬(ADR / 이슈 스펙 / 코드·테스트) |

**주의 (흔한 오해)**
- 9·10·12·13장: ADR 서식은 Nygard 원형 → MADR → 강사 서식. 13장 대응표는 강사가 항목 이름을 맞춰 본 것이지 공개 서식에 같은 이름 칸이 있다는 뜻이 아니다. MADR의 확인 칸은 ‘다시 판단할 조건’과 성격이 다르다.
- 16·17장 예시 ADR은 교육용 가상 프로젝트(실제 기록 아님).
- 19장 “ADR이 에이전트에게 좋다”는 강사 운영 경험이며 모든 프로젝트에서 이득을 측정한 것이 아니다.
- 23장 네 계층(마일스톤·스테이지·스프린트·Task)은 교육용 구체화이며 GitHub 별도 기능이 아니다. 하위 이슈 제한은 GitHub 문서 수치.
- 24장 이슈 병합 도식은 가상 예시. 중복 정리로 닫은 이슈는 수정 완료가 아니다. 25장: 부분 반영·단순 연관은 `Related`, 사이드바 수동 연결 이슈는 머지 때 닫힐 수 있어 연관 표시로 쓰지 말 것. 키워드는 기본 브랜치 대상 PR에서만 해석.
- 초안은 에이전트가 써도 ‘승인됨’과 사용자 판단 칸은 사람이 채운다(20장, 17장 예시).
- 26장 18단계는 기본 사고 순서이며 작은 프로젝트에서는 합치거나 생략한다.

**예상 질문**

- “이슈를 합치는 기준은?” → 함께 검토하고, 출시하고, 되돌릴 수 있는가.

### 15교시 · CI 폭증·머지 큐와 스모크 테스트 (26장, 60분)
목표: CI(Continuous Integration, 지속적 통합) 비용 폭증의 원인(단가 아닌 실행량)과 줄이는 순서를 알고, 초록불을 믿지 않고 스모크 증거를 남기는 법을 말하게 한다.
| 구간 | 장 | 분 | 꼭 짚을 말 |
| --- | --- | --- | --- |
| 열기 | 1–2 | 3 | 두 병목: CI 줄 서기, 통과가 곧 동작은 아님 |
| 비용 사실 | 3–5 | 8 | 단가는 내림(호스티드 러너 최대 39%, 2026-01-01). 실행량 폭증(2026-09 한 달 32.6억 회, 1년 전 4배·커밋 73.8억). Anthropic 하루 머지 30,401건(9월 9일), Scion(2026-10-13) |
| 줄이는 순서 | 6–10 | 11 | 횟수×시간×단가 중 앞 둘. 1 취소(concurrency, pull_request일 때만) 2 거르기(paths, 필수 검사 함정) 3 캐시 4 머지 큐. 영향받는 검사 선택은 DDD(Domain-Driven Design, 도메인 주도 설계) 경계가 전제(10장) |
| 머지 큐 ① | 11–12 | 6 | 2023-07-12 GA, 줄 세워 합친 상태로 먼저 검사, 누적 후보 검증, 실패 시 재구성 |
| 질문 시간 | 13 | 5 | 비용 사실·줄이는 순서·머지 큐 개념까지 질문 받기 |
| 머지 큐 ② | 14–16 | 7 | `merge_group` 이벤트 필수, 게이트 job. GitLab은 머지 트레인(Premium·Ultimate). 병렬화는 대기를, 범위 축소는 러너·분을 줄인다 |

**주의 (흔한 오해)**
- “Actions 과금이 올랐다”가 아니라 “단가는 내렸고 실행량이 폭증”. 셀프호스티드 러너 신규 과금은 보류(3장).
- 경로 필터로 필수 검사 워크플로를 통째로 건너뛰면 상태가 보고되지 않아 PR(Pull Request, 변경 병합 요청)·머지 큐가 기다린다. 진입·분석·최종 게이트는 항상 실행(8장).
- 머지 큐에서 취소 concurrency를 후보에 걸면 후보끼리 필수 검사를 끊는다. `merge_group` 이벤트를 안 받으면 큐가 멈춘다. 게이트의 `always`는 항상 성공이 아니며 실패·취소·예상 밖 skip을 통과로 바꾸면 안 된다(14장).
- 머지 큐는 충돌 해결·검토 대체 도구가 아니고 제공 범위(조직 공개 저장소·Enterprise Cloud 비공개)를 확인. 실패가 잦으면 오히려 대기가 늘 수 있음.
- 16장 표는 제품 실측이 아닌 교육용 가정(러너 3개: 36분 → 12분이나 사용량 36 러너·분 동일). “최대 병합 3 → 비용 1/3”으로 계산 금지.
- Claude in Chrome은 로그인 상태를 공유하므로 테스트 계정과 개발 환경만(21장). computer use는 실험적이고 웹 검증엔 브라우저 도구가 더 정확(18장).

**예상 질문**
- “CI 비용을 가장 먼저 줄이려면?” → 낡은 실행 취소, 관계없는 검사 거르기처럼 앞 단계일수록 쉽고 안전.
- “캐시해도 되나요?” → 의존성은 lock 해시 키로. 테스트 결과를 캐시해 변경된 코드를 건너뛰면 안 됨(9장).

**주의 (흔한 오해)**
- 가상 사용자는 사전 점검이지 최종 판정이 아니다. TinyTroupe README도 산출물을 통찰용으로 쓰고 직접적 의사결정에 쓰지 말라고 경고. UXAgent의 목적은 실제 사람 실험 전 설계 점검(6장).
- 포기 조건이 없으면 에이전트는 끝까지 성공해 버린다. 페르소나를 상상으로 쓰면 실제 고객의 문제가 안 나온다. 가상 페르소나는 근거 한 줄 필수(8장 예시 인물도 가상).
- REA 설명은 README에 있는 내용만 말한다(15장). 허가받은 소프트웨어(내 소유이거나 분석 허가)에만 쓴다는 점을 반드시 언급(17장). RL(Reinforcement Learning, 강화학습) 환경 가이드(녹화한 웹앱 세션을 에이전트용 환경으로)는 확장 방향의 관찰.
- 실습은 설치·문법·코드 검토가 아니다. 질문 → ADR 승인 → 시키기 → 스모크로 확인 → 어겨 보기 → 기록 순서이고, 승인은 사람만 한다(20장). 실습 장에는 코드 블록(PR 본문·CI YAML(YAML Ain't Markup Language, 설정 기록용 서식)·머지 명령·next-update 파일)을 두지 않는다. 결과 예시 줄·표는 모두 ‘예시’로 밝혀 둔 가상 값. 시간이 빠듯해 질문 시간(13장)이나 REA(15–17장)를 줄여 실습 25분을 확보한다.
- CI는 `main 보호: CI 통과 필수`를 켜지 않으면 빨개도 머지된다(21장). 머지 후 스모크는 CI·스테이징 확인을 대신하지 않고, 실패하면 이슈를 다시 열고 그 커밋을 배포 후보에서 뺀다(22장). 정기 배포·스테이징은 개인 도구나 PoC(Proof of Concept, 개념 증명)에는 필요할 때만. 21장 예시는 GitHub Actions·파이썬 기준이라 자기 도구로 바꿔 달라고 한다.
- 이슈 문장이 에이전트에게 새 권한을 주지 않는다. 증거 없는 판정은 이슈 금지, 평가는 최대 2바퀴, 버그·문구 수정은 워커에 자동 배치, ADR 변경·범위 변경·고복잡도는 사람 판단(24장). 14교시 이슈 원장 없이는 페르소나 이슈를 워커가 집어 갈 수 없고(11장), 상한 없는 자기 개선 루프는 사소한 불편만 계속 고친다(12·25장).
- 29장 실행 기록 표 값은 양식용 가상 값이고 이야기할 때 쓸 수 있는 예일 뿐 제출물이 아니다. 토큰은 도구의 사용량 화면이나 API(Application Programming Interface, 프로그램 연동 규약) 응답의 usage에서 읽고, 실패한 회차를 지우지 않는다. 14장 실행 화면은 교체 예정이라는 점을 밝힌다.
