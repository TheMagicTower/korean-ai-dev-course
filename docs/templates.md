# 실무·실습 템플릿

필요한 부분을 복사해 프로젝트 저장소 또는 작업 기록에 작성합니다. 민감한 키와 개인 자료는 기록하지 않습니다.

## 프로젝트 계약

```text
프로젝트 이름:
사용자와 해결할 문제:
사용 범위 (개인 / 팀 / 외부 사용자):
목표 단계 (PoC / MVP / 프로덕션 또는 개인 완성 도구):
실패 피해와 실제 위험:
핵심 사용자 흐름 하나:
필수 기능 (최대 3개):
이번 과정에서 제외할 기능:
데이터·결과 유지 방식:
전달 방식 (주소 / 실행 패키지 / 재현 명령):
사용할 도구와 접근 가능한 모델:
대표 성공 시나리오:
대표 실패 시나리오:
완성품으로 인정할 증거:
예상 비용·사용량 한도:
세션 시간·재시도 한도 (미측정 토큰은 미확인):
필수 검증과 생략할 절차·이유:
리뷰 범위·횟수·종료 조건:
예산 소진 시 처리 (미완료 인계 / 범위 재합의):
범위 변경 이력과 이유:
```

## 분석에서 프로젝트 개요까지

작은 프로젝트는 아래를 한 문서에 작성합니다. 조사하지 않은 내용은 가정·미확인으로 표시합니다.

```text
누가 어떤 환경에서 쓰는가:
적정 사용 난이도·사용자 숙련도·접근성 요구:
보안·역할·접근 경계와 결정 이유:
비즈니스 레이어 (현재 업무·규칙·예외·책임·성과):
사용성 레이어 (행동·빈도·불편·실수·회복):
조사 방법·근거·미확인 가정:
대표 시나리오·시작 조건·획득할 결과:
입력 형식·제약 → 기대 출력·실패 출력·부작용:
시장성 또는 개인 효용·대체재·차별점·확인 근거:
프로젝트 개요·포함/제외·완료 수준:
가이드라인 (프레임워크·언어·인프라·솔루션·외부 상호작용):
Spec 개요 (기능·비기능·인터페이스·수용 기준):
```

비교 기준이 추정이면 결과도 추정으로 표시합니다. 구현 속도비를 전체 개발 속도비나 비용 절감률로 바꾸어 표현하지 않습니다.
