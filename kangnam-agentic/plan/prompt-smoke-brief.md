# 실습 장 재구성: 프롬프트 + 스모크 (2026-10-29 11:19 강사 결정)

강사 말: “모든 강의 실습은 어차피 하네스한테 시키고 코드는 보지도 않을 건데 저렇게 하는 게 의미가 있나?” → “프롬프트와 스모크 기반이 훨씬 상식적이다.”

## 원칙
1. 학생은 **코드를 읽지 않는다.** 실습 장에서 코드 블록(셸 스크립트, JSON 설정, YAML, SKILL.md 본문, 루프 코드)과 `# ①` 같은 코드 검토 표시를 **뺀다.** 장점·단점·의미 카드(.pmi) 중 코드 내용을 설명하던 것도 같이 뺀다.
2. 실습 장 하나는 두 부분이다.
   - **프롬프트**: 하네스(학생이 쓰는 에이전트)에게 그대로 붙여 넣을 문장(`.term`). 무엇을 만들라가 아니라 “무엇을 원하고, 어떤 조건이면 끝이고, 끝나면 무엇을 보여 줘”까지.
   - **스모크(동작 확인)**: 코드를 보는 대신 **실제로 돌려서 확인**한다. 하네스에게 시켜서 보여 달라고 하는 증거와, 학생이 직접 해 보는 짧은 시나리오. 예) 금지 규칙을 일부러 어기는 요청을 하고 막히는지 본다 / 앱을 띄워 핵심 흐름 3개를 눌러 보고 화면을 남긴다 / 테스트·CI 결과 요약을 보여 달라고 한다 / 실행 시간·토큰 기록.
   - 스모크는 `.term`으로 “학생이 한 말 → 하네스가 보여 준 결과(예시)” 대화 형태로 보여 주거나, 표(시나리오 · 기대 결과 · 실제 결과 · 통과)로.
3. 사람이 보는 것은 세 가지뿐: **에이전트의 질문에 내가 한 답**, **에이전트가 정리한 결정(개요·ADR·스펙의 한 줄 요약)**, **스모크 결과**. “승인 전 체크리스트”는 코드가 아니라 이 세 가지에 대한 체크로 바꾼다.
4. 4교시 ‘바로 시키면 vs 질문부터’, 설계 질문 표, 18단계·이슈 워크플로우 단계 표시(tag)는 유지한다.
5. 과제 제출물: 쓴 프롬프트와 대화 기록, 결정 문서(개요·ADR·스펙), **스모크 기록**(시나리오 표 + 화면·로그), 실행 기록. 저장소 링크는 유지하되 코드 품질은 평가하지 않는다. 기한은 그대로, 배점은 이 항목에 맞춰 합 100.
6. ‘막힐 때’ 표는 유지(증상 → 하네스에게 다시 할 말). 코드 관련 증상은 스모크 증상으로 바꾼다(예: “스모크에서 막혀야 할 요청이 통과됐다 → ‘방금 요청이 왜 통과됐는지 설명하고, 막히게 고친 뒤 같은 요청으로 다시 보여 줘’”).
7. 장 수는 줄어도 된다. 모든 장에 이미지·도식·표·`.term` 중 하나. 기존 캡처 재사용 가능. 노트(aside)는 합니다체, 소개하는 말투(“저는 이렇게 시킵니다”), 3~7문장. 설치 안내 없음.
8. 사실·날짜를 새로 만들지 않는다. 스모크 결과 예시는 “예시”라고 tag나 .kind에 밝힌다.
