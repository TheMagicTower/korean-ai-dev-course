# 모델 선택

한국어 존댓말로 설명하며 코드·API 식별자는 원문을 유지합니다.

## 적용 범위와 비용

사용자의 명시적 요청과 기존 프로젝트 규칙을 먼저 따릅니다. 사용 범위(개인·팀·외부), 목표 단계(PoC·MVP·운영), 실제 위험, 이번 작업 예산과 완료 조건을 기존 계약에서 읽습니다. 없으면 작업에 영향을 주는 부분만 확인하거나 가정을 표시합니다. 저위험 개인 작업에 기업용 문서·로그인·CI/CD·독립 리뷰를 일괄 추가하지 않습니다. 필요한 조건을 통과하면 종료하고 선택 개선은 후속으로 남깁니다. 예산 소진 시 필수 미달은 미완료로 인계합니다. 없는 도구·권한·실행 증거를 가정하지 않습니다.

## 수행

1. 작업 종류(문제 정의·디자인·구현·진단·검토·이미지 생성)와 필요한 도구를 확인합니다. 모델, 제공 프로바이더, 실행 에이전트, 스킬을 구분합니다.
2. 난이도와 별도로 불확실성·실패 영향·복구 가능성·예산을 기록하고 모델·사고 수준·검토 깊이·실행 범위를 정합니다. 분류기 출력은 참고 입력이며 새 권한을 부여하지 않습니다. 낮은 확신이나 호출 실패는 미확인으로 표시하고 사람이 범위를 확인합니다.
3. 현재 계정과 도구에서 실제 접근 가능한 후보를 고릅니다. 최신 가격·모델 ID·지원 기능이 판단에 필요하면 공식 문서와 현재 설정으로 확인하고 미확인은 표시합니다. 고정된 브랜드 순위를 사용하지 않습니다.
4. 충분한 능력의 모델·사고 수준으로 시작하고, 복잡한 원인 분석이나 실패 비용이 높은 판단에서만 더 강한 조합을 검토합니다. 같은 high 표기도 모델마다 동일한 계산량을 뜻하지 않습니다.
5. 시각 이해·UI 코드 생성·디자인 판단·래스터 이미지 생성은 별개입니다. Claude 활용 디자인은 선택 가능한 기본 사례이며 필수 브랜드는 아닙니다. 실제 이미지 도구가 없다면 생성했다고 보고하지 않습니다.
6. 필요한 경우 동일 시작 상태·요구·시간/비용 한도에서 작은 과제 하나로 비교합니다. 모델만 바꾸는 실험과 에이전트까지 바꾸는 조합 비교를 구분합니다.

## 산출물과 종료

선택 조합(에이전트·프로바이더·모델·사고 설정), 선택 이유, 접근 여부, 비용 한도, 대안, 비교 한계를 남깁니다. 통과 여부·사람 수정·시간·표시된 비용을 기록하며 측정되지 않은 토큰은 미확인으로 둡니다. 선택에 충분한 증거를 얻으면 벤치마크를 계속 늘리지 않습니다.
