# 2주차 · 목업에서 규칙을 도출합니다

오늘의 산출물은 **선택한 목업, 실제 계약, 끝까지 연결된 핵심 흐름**입니다. DB를 먼저 확정하기보다 화면과 결과를 조작하며 필요한 내부 구조를 도출합니다.

## 120분 진행표

| 시간 | 활동 | 결과 |
|---|---|---|
| 0–10 | 실제 상태·범위 복원 | 시작 버전 |
| 10–25 | 목업 조작·규칙·API·데이터 도출 | 작은 설계 |
| 25–40 | 임시 동작을 실제 저장에 연결하는 시연 | 작업 분할·검증 |
| 40–50 | 휴식 | |
| 50–105 | 개인 프로젝트 핵심 흐름 구현 | 입출력 연결 |
| 105–120 | 직접 실행·인계 | 증거·남은 작업 |

## 개념 — 목업은 질문을 구체적으로 만듭니다

‘처리 완료’ 버튼을 눌러 보고 누가 실행할 수 있는지, 다시 누르면 어떻게 되는지, 취소할 수 있는지, 새로고침 후 유지되어야 하는지를 정합니다. 화면의 색을 DB 필드로 옮기는 것이 아니라 데이터의 의미와 규칙을 찾습니다.

| 관찰 | 도출할 계약 | 검증 예시 |
|---|---|---|
| 완료 버튼 | 허용된 상태 전이 | 이미 완료된 건 재실행 |
| 문의 내용 입력 | 필수값·길이·오류 | 빈 내용 입력 |
| 상태 유지 | 저장 범위·데이터 관계 | 재실행 후 같은 상태 |
| 담당자별 행동 | 접근 권한 | 권한 없는 변경 거부 |

개인 로컬 도구라면 서버 API·DB 서버 대신 함수와 로컬 저장 계약이면 충분할 수 있습니다. 반대로 여러 사람의 비공개 자료를 다루면 화면에서 숨기는 것만으로 접근 통제가 되지 않습니다.

## 강사 시연 — 하나의 규칙을 실제 동작으로

임시 배열의 상태를 바꾸는 문의 목업을 사용합니다. 처리 상태를 저장하는 계약을 정의하고 실제 저장을 연결합니다. 저장 실패를 성공으로 표시하지 않는지 확인하고, 재실행으로 유지 여부를 검증합니다. 시연할 코드와 오류는 사용 환경에 맞춰 수업 전에 실제 실행해 둡니다.

```text
목업과 설계·작업 계획 스킬을 사용해 현재 목업을 읽어 주세요. 임시 동작·미구현 저장·권한을 먼저 표시하고, 처리 완료 행동에서 업무 규칙·입출력·저장 계약을 도출해 주세요. 개인용 로컬 도구이므로 서버와 로그인을 임의로 추가하지 마세요. 중요한 결정은 짧게 기록하고 구현할 작업과 검증 방법을 나눠 주세요.
```

## 실행 계획은 무엇이 달라야 합니까?

Spec은 맞는 동작, 계획은 변경할 위치와 순서입니다. ADR은 중요한 선택의 배경·대안·이유·영향을 남깁니다. 모든 작은 수정에 긴 ADR을 만들 필요는 없습니다.

운영형 계층은 **마일스톤 → 작업 스테이지 → 스프린트 → Task**입니다. 이번 작은 과제에서는 한 문서의 목록으로 표현해도 됩니다. AI 세션은 실행 맥락, 워크트리는 격리 공간, PR은 통합 단위입니다. 이들을 같은 것으로 취급하지 않습니다.

## 내 프로젝트 실습

```text
기능 구현 스킬을 사용해 합의한 계획의 첫 핵심 흐름을 구현해 주세요. 먼저 현재 변경과 관련 ADR·Spec을 확인하고 제 작업을 보존해 주세요. 필수 범위는 [범위]이며 제외는 [제외]입니다. 완료 조건은 [입력→결과와 확인 방법]입니다. 목업의 가짜 동작과 실제 구현을 구분하고, 확인한 결과·미확인·남은 필수 작업을 알려주세요.
```

구현 전에 완료 조건 하나를 직접 읽어 봅니다. 에이전트가 “끝났다”고 하면 자신의 입력으로 확인합니다. 예상과 다르면 전체 재작성 대신 어떤 입력에서 달라지는지 기록합니다.

## 오늘의 완료 확인

- [ ] 목업에서 규칙·기능·API 또는 함수·데이터를 도출했습니다.
- [ ] 임시 동작과 실제 구현을 구분했습니다.
- [ ] 입력부터 결과까지 한 흐름을 실행했습니다.
- [ ] 필요한 저장·대표 실패와 남은 필수 작업을 기록했습니다.
