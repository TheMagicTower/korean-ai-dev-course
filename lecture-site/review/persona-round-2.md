# 가상 수강생 인지 워크스루 · 2차

## 방법과 읽은 자료

이 점검은 **같은 다섯 가상 수강생을 유지한 문서 기반 인지 워크스루**입니다. 실제 수강생의 발언, 실습 실행, 성취도나 완료 시간을 관찰한 결과가 아닙니다. 아래 모의 답변은 페르소나의 배경과 자료에 근거해 작성한 **예상 이해·다음 행동·제출물 설명**입니다. 이 답변이 그럴듯하다는 이유로 실제 학습 효과가 입증되었다고 판정하지 않습니다.

기준 페르소나와 질문은 [personas.json](./personas.json), 초기 진단은 [persona-round-1.md](./persona-round-1.md)입니다. 페르소나 ID와 25개 질문 ID를 그대로 유지했습니다. 강사 노트는 학생이 읽을 수 있는 자료로 포함했습니다. 기술 문헌 사실 검증과 코드 전체 리뷰, 실제 브라우저 실행은 이 점검의 범위가 아닙니다. 실습 파일의 이름·공개 함수·화면 식별자는 **지시한 행동을 학생이 이어갈 수 있는지** 확인하는 범위에서만 읽었습니다.

처음 읽은 개편안은 `content/revision/session-1.json`부터 `session-5.json`까지입니다. 아래 기록에는 당시 발견한 막힘을 남깁니다. 집필자가 이후 고친 내용을 소급해 처음부터 해결돼 있었다고 쓰지 않으며, 최종 통합본은 3차 점검에서 다시 확인합니다.

판정은 `자료상 해결 / 일부 해결 / 미해결 / 확인 불가`를 사용합니다. **자료상 해결은 해당 질문에 답할 설명·예제·절차가 있다는 뜻이며 실제 학생의 성공을 뜻하지 않습니다.** 슬라이드 개수, 단어 수, 시간 합계만으로 해결 판정을 내리지 않았습니다. 1개·9개·27개 같은 수치는 자료가 제시한 현재 스냅샷의 **기대값**으로 인용하며, 이번 점검에서 측정한 실행 결과가 아닙니다.

- **3차 확인:** 발표 뒤 입력·데이터·사용 조건 하나를 바꾼 짧은 질문을 추가하거나, 해당 역량의 확인 범위를 제한해서 명시하는지 확인합니다.

## 운영 시간과 학습 효과의 해석

- 개편안에는 실습별 중간 점검·대안·심화·제출물이 있어 기존 큰 제작 블록보다 전환 기준이 분명합니다. 이것만으로 실제 학생이 배정 시간 안에 끝낸다고 검증한 것은 아닙니다.
- 가장 큰 시간 위험은 일반적인 코딩 난도보다 **잘못 연결된 파일·계약을 학생이 스스로 해석해야 하는 시간(R2-02)**, 작업 준비·보존 절차(R2-04·05), 처음 설치·가입·공개를 동시에 하는 시간(R2-06)입니다.
- 4회차 수동 경로와 5회차 공개 데모 대안은 학습을 이어갈 수 있게 합니다. 다만 이 대안으로 진행했다고 자기 제품의 네트워크 실패 검사나 공개 MVP가 완료되는 것은 아닙니다. 개편안은 이 구분을 명시합니다.
- 5회차 짝 발표는 11분에 두 사람의 발표와 상호 질문을 배치합니다. 전체 학생이 순차 발표하는 계획으로 잘못 읽지 않도록 합니다. 강사가 모든 학생의 이해를 깊게 평가할 수 있는지는 실제 인원·운영과 별도 확인이 필요합니다.
- 최종 통합본 3차에서는 R2-01~06과 P04-S5의 평가 보강을 같은 질문으로 확인합니다. 실제 학습 효과는 파일럿 또는 수업 중의 시작 지연, 도움 요청, 제출물, 자기 설명을 관찰한 뒤에만 판단합니다.
