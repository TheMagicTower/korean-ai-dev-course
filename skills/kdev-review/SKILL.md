# 변경 검토

한국어 존댓말로 설명하며 코드·API 식별자는 원문을 유지합니다.

## 적용 범위와 비용

사용자의 명시적 요청과 기존 프로젝트 규칙을 먼저 따릅니다. 사용 범위(개인·팀·외부), 목표 단계(PoC·MVP·운영), 실제 위험, 이번 작업 예산과 완료 조건을 기존 계약에서 읽습니다. 없으면 작업에 영향을 주는 부분만 확인하거나 가정을 표시합니다. 저위험 개인 작업에 기업용 문서·로그인·CI/CD·독립 리뷰를 일괄 추가하지 않습니다. 필요한 조건을 통과하면 종료하고 선택 개선은 후속으로 남깁니다. 예산 소진 시 필수 미달은 미완료로 인계합니다. 없는 도구·권한·실행 증거를 가정하지 않습니다.

## 수행

1. 검토 대상(스펙·계획·구현), 원본 변경·버전·요구·ADR·수용 조건을 읽습니다. 작성자의 완료 주장만을 근거로 판정하지 않습니다.
2. 스펙은 올바른 동작·모호성·누락을, 계획은 범위·의존·검증 가능성을, 구현은 실제 변경과 계약·실행 증거를 확인합니다.
3. 선택한 수준의 핵심 목적을 막거나 실제 위험 경계를 깨는 항목을 블로커로 판정합니다. 심각도 명칭보다 영향·근거를 설명합니다. 개인 도구에 요구되지 않은 조직 기능·운영 인프라의 부재를 블로커로 만들지 않습니다.
4. 각 지적에 위치·재현 또는 근거·영향·필요한 조치를 남깁니다. 제안과 확인된 오류를 구분합니다. 검토만 요청된 경우 파일을 수정하지 않습니다.
5. 수정 후에는 해당 지적과 영향을 재검토합니다. 필수 기준 충족·블로커 없음이면 종료합니다. 비차단 개선은 후속으로 남기고 새로운 근거 없이 전체 리뷰를 다시 시작하지 않습니다.
6. 저위험 작업은 자체 확인으로 충분할 수 있습니다. 독립 검토가 필요한 위험 경계는 별도 검토자를 사용하되, 다른 모델이라는 이유만으로 독립성이 보장된다고 말하지 않습니다.

## 산출물과 종료

판정(통과·블로커 잔존·증거 부족), 블로커, 비차단 후속, 검증 범위·미확인을 기록합니다. 지적이 없으면 억지로 만들지 않습니다. 예산이 소진되고 블로커가 남으면 통과가 아니라 중단·인계입니다.
