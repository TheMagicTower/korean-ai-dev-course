# 외부 운영 사례 · Linear CI 최적화

Linear의 운영 보고를 수업용으로 정리한 사례입니다. **사실과 수치의 근거는 Linear 원문이며, 이 저장소 실측이 아닙니다.** 데모·측정 제공 없이 적용 조건을 따지는 용도입니다.

- 원문: [AI coding has made CI a bottleneck, so we reworked ours to keep up](https://linear.app/now/ci-bottleneck-reworked) — Mufeez Amjad, Linear, 게시 2026-09-21, 확인 2026-09-28
- 2차 소개: [파파누보의 티스토리 글](https://digitalbourgeois.tistory.com/m/3691)(2026-09-27)은 위 원문을 연결한 소개이며, 사실과 수치의 근거는 원문입니다.

## 원문이 보고한 결과 (Linear 자체 보고)

AI 코딩 확산으로 테스트가 늘어 PR 검증 완료까지 전체 시간이 늘었다고 보고했습니다. 대응은 실행 환경·도구 손질, 앞 단계 정리, 반복 준비 낮추기, 테스트 나누기였습니다. 아래 수치는 Linear의 자체 보고이며 강의 측정값이 아닙니다. 'CI 대기'는 대기열이 아니라 PR 검증 완료까지의 전체 시간입니다.

| 항목 | 원문 보고 |
|---|---|
| PR 검증 대기 | 6분 초과에서 5분 남짓으로 |
| 테스트당 시간 | 약 절반으로 |
| 변경 감지 중앙값 | 26초에서 8초로 |
| node_modules 준비 | 캐시 복원 28초 대비 선별 설치 약 7.5초로 |

캐시 복원·선별 설치 비교이며 절감 보장으로 쓰지 않습니다.

## 학습 해석 (원문 주장이 아닌 우리 해석)

아래 연결은 우리 강의의 해석입니다. 원문은 DDD·TDD 전환을 주장하지 않습니다.

- 도메인 의존 방향은 DDD로 설계하고, 선택 검사를 하기 전에 실제 테스트 격리(공유 상태·순서 의존 없음)를 따로 확인합니다. 자세한 조건은 [DDD·TDD와 테스트 경계](../domain-testing.md)를 보세요.
- 영역별 TDD로 작은 규칙을 고정하고 경계 계약을 검사합니다. 누적 후보의 검사 범위는 변경의 역방향 의존 닫힘에 항상 실행하는 통합·계약 게이트를 더한 것이며, 공용 설정 변경이나 영향 불명 시 전체 검사를 실행합니다. DDD·TDD만으로 선택이 자동화되지 않습니다. 자세한 절차는 [병렬 AI 개발과 머지트레인](../parallel-ai-merge-train.md)을 보세요.
- Vitest 파일 실행 격리(`isolate:false`)는 DDD 의존성 경계와 다릅니다. 원문도 안전 판정 파일에만 파일별 표시로 opt-in 했고, fake timers·정리 어려운 파일은 기존 격리를 유지했으며 생성 테스트용 에이전트 스킬을 갱신했습니다. 전역 적용은 권장하지 않습니다.

## 적용 전 확인 조건

원문을 그대로 옮기기 전에 아래를 먼저 확인합니다.

- 내 CI에서 가장 오래 걸리는 경로를 대기열 시간과 단계 실행 시간으로 나눠 측정합니다.
- 반복 준비 비용(의존성과 실행 환경 준비)이 실제 병목인지 확인합니다.
- 벽시계 시간과 러너 사용량을 나누어 기록합니다.
- 캐시가 없어도 빌드·테스트·배포가 재현되는지와 원상복귀 방법을 정합니다.
- 필수 검사를 생략하거나 결과 캐시만으로 검사를 건너뛰지 않습니다.

## 4주차 회고 5분 대체 연습

기존 110–120분 회고 중 5분을 이 연습으로 대체합니다. 필수 완료가 늦으면 추가 분석보다 수정과 전달을 우선합니다.

| 적을 항목 | 내 기록 |
|---|---|
| 내 CI에서 가장 오래 걸리는 경로 | |
| 반복 준비 비용(의존성·환경 준비) | |
| 벽시계 시간과 러너 사용량 구분 | |
| 원상복귀 조건(캐시 없이 통과하는 방법) | |

## 짧은 문제와 해설

1. **문제:** 'CI 대기'는 대기열인가요? **해설:** 아닙니다. PR 검증 완료까지의 전체 시간이며 대기열은 그 일부입니다.
2. **문제:** `isolate:false`를 모든 파일에 적용해도 되나요? **해설:** 안 됩니다. 실행 격리와 DDD 경계는 다르며, 원문도 안전 판정 파일에만 파일별 표시로 opt-in 했습니다.
3. **문제:** DDD 경계만으로 나머지 검사를 생략해도 되나요? **해설:** 안 됩니다. 역방향 의존 닫힘과 필수 통합·계약 게이트가 필요하고, 공용 변경·영향 불명 시 전체 검사를 실행합니다.
