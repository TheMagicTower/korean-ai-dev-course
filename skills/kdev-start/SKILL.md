# 프로젝트 시작

한국어 존댓말로 설명하며 코드·API 식별자는 원문을 유지합니다.

## 적용 범위와 비용

사용자의 명시적 요청과 기존 프로젝트 규칙을 먼저 따릅니다. 사용 범위(개인·팀·외부), 목표 단계(PoC·MVP·운영), 실제 위험, 이번 작업 예산과 완료 조건을 기존 계약에서 읽습니다. 없으면 작업에 영향을 주는 부분만 확인하거나 가정을 표시합니다. 저위험 개인 작업에 기업용 문서·로그인·CI/CD·독립 리뷰를 일괄 추가하지 않습니다. 필요한 조건을 통과하면 종료하고 선택 개선은 후속으로 남깁니다. 예산 소진 시 필수 미달은 미완료로 인계합니다. 없는 도구·권한·실행 증거를 가정하지 않습니다.

## 수행

1. 누가 어떤 상황에서 쓰는지, 적정 사용 난이도와 접근·보안 경계를 확인합니다. 비즈니스 레이어(업무·책임·규칙·예외)와 사용성 레이어(행동·숙련도·불편·회복)를 구분합니다.
2. 대표 사용 예제와 획득할 결과를 입력 → 행동 → 출력으로 적습니다. 정상·대표 실패 조건을 포함합니다.
3. 시장성·유사 제품·차별점은 출처가 있는 사실과 가설을 나눕니다. 개인용은 시장 규모 대신 대체재와 직접 만들 효용·유지 비용으로 충분합니다. 최신 경쟁 정보가 필요하면 사용할 수 있는 검색 도구로 확인합니다.
4. 목적·포함/제외·사용 수준·필수 완료 증거·시간/비용 예산을 짧은 프로젝트 계약으로 정리합니다. 부족한 정보가 있더라도 확인된 부분부터 작성합니다.
5. 적용할 절차와 생략 이유를 계약에 남깁니다. 개인·팀·외부의 사용 범위와 PoC·MVP·운영 단계를 별도로 기록하며, 공유 사용·데이터 손실·비용 등 위험이 바뀌면 필요한 절차만 다시 판단합니다. 작은 프로젝트는 개요·Spec·ADR·계획을 한 문서에 통합할 수 있습니다.
6. 다음 행동은 문제와 제약을 입력으로 AI 목업·프로토타입을 만들어 보는 것입니다. 상세 DB 설계를 먼저 고정하지 않습니다. 실제 데이터·권한 등 선행 제약은 보존합니다.

## 산출물과 종료

프로젝트 개요, 핵심 시나리오·입출력, 조사 근거/가정, 완료 수준, 포함/제외, 예산, 다음 실험을 남깁니다. 핵심 목적과 판정 가능한 완료 조건이 정리되면 종료합니다. PoC의 가설 기각도 실험 완료일 수 있지만 제품 완성이라고 표현하지 않습니다. 질문만 반복하거나 요청 없는 구현을 시작하지 않습니다.
