# 완성품 확인

한국어 존댓말로 설명하며 코드·API 식별자는 원문을 유지합니다.

## 적용 범위와 비용

사용자의 명시적 요청과 기존 프로젝트 규칙을 먼저 따릅니다. 사용 범위(개인·팀·외부), 목표 단계(PoC·MVP·운영), 실제 위험, 이번 작업 예산과 완료 조건을 기존 계약에서 읽습니다. 없으면 작업에 영향을 주는 부분만 확인하거나 가정을 표시합니다. 저위험 개인 작업에 기업용 문서·로그인·CI/CD·독립 리뷰를 일괄 추가하지 않습니다. 필요한 조건을 통과하면 종료하고 선택 개선은 후속으로 남깁니다. 예산 소진 시 필수 미달은 미완료로 인계합니다. 없는 도구·권한·실행 증거를 가정하지 않습니다.

## 수행

1. 계약한 사용자·완료 수준·전달 방식·필수 조건·실제 위험을 읽습니다. 개인용에 기업용 운영 체크리스트 전체를 적용하지 않습니다.
2. 전달 대상 버전에서 핵심 흐름·대표 실패·필요한 결과 유지·사용 안내를 확인합니다. 저장이 필요 없는 도구는 출력과 재실행으로 검증합니다. 본인용은 새 세션 재실행, 타인용은 대상 사용자의 실행·피드백을 확인합니다.
3. 실제 키·불필요한 민감정보가 제출물에 없는지 확인합니다. 원본 삭제·다중 사용자·외부 전송·공개 API 등 실제 위험이 있으면 해당 복구·권한·중복·비용 제한을 확인합니다.
4. 운영형은 구현 리뷰 → PR → 해당 버전 CI → 스쿼시 머지 → 머지 후 스모크의 증거를 연결합니다. 실제 수행 요청이 없는 머지·배포는 실행하지 않고 준비 상태를 보고합니다.
5. 정기 CD를 쓰는 프로젝트는 일별 프리릴리즈·스테이징 스모크, 주별 릴리즈·운영 확인을 구분합니다. 배포 주기 자체는 프로젝트 선택이며 이 스킬이 새 스케줄을 만들지는 않습니다. 실패 후보는 시각이 되었다는 이유로 승격하지 않습니다.
6. 검증한 버전과 전달 버전을 일치시키고 변경되면 영향 있는 흐름을 재확인합니다. 코드 재사용이나 CI 통과만으로 실제 사용을 완료 처리하지 않습니다.

## 산출물과 종료

버전·환경·일시·기대/실제 결과·증거·판정, 사용법·제한·다음 개선을 남깁니다. 필수 미확인 또는 실패가 있으면 준비/미완료로 표시합니다. PoC 결론·제품 완성·운영 출시를 별도 상태로 보고합니다.
