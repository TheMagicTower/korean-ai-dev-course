자동완성: 커서 앞뒤 코드를 보고 가운데 채우기

{{svg:p02-fim}}

예전에는 커서 앞만 프롬프트였습니다. 뒤 코드까지 알려 주자 중간에 끼워 넣는 제안이 좋아졌습니다.

자동완성 모델은 원래 앞의 글을 보고 뒤를 이어 쓰는 모델입니다. 그러면 파일 중간에 코드를 끼워 넣을 때는 불리합니다. 그래서 커서 앞의 코드와 뒤의 코드를 둘 다 모델에게 주고, 가운데를 채우게 합니다. 이것이 FIM(Fill-in-the-Middle, 가운데 채우기)입니다. GitHub 엔지니어링 글에 따르면 이전에는 커서 앞의 코드, 프리픽스만 프롬프트에 들어갔고, FIM에서는 뒤의 코드, 서픽스도 함께 넣습니다. 제안은 회색 글씨로 보이고 Tab으로 수락합니다.

github.blog/ai-and-ml/github-copilot/how-github-copilot-is-getting-better…
GitHub Blog · 2023-05-17
GitHub 글. FIM을 Copilot에 넣어 코드 이해가 좋아졌다고 소개.
FIM 적용 후 A/B 테스트(두 버전 비교)에서 수락된 제안이 상대적으로 10% 증가했다.
상대 10%는 수락 건수가 1.1배라는 뜻이다. 수락률이 10포인트 오른 것이 아니다.
학습법 논문과 실제 제품 실험 양쪽에서 확인되어, 앞 장의 “앞뒤를 보고 채운다”는 설명의 근거가 된다.
왼쪽은 OpenAI 연구자들이 2022년 7월에 낸 논문으로, 문서 가운데의 구간을 끝으로 옮겨 학습하면 모델이 빈칸을 채우는 법을 배우고 일반 생성 능력도 떨어지지 않는다는 내용입니다. 오른쪽은 GitHub이 2023년 5월 이것을 Copilot에 적용한 결과를 적은 글입니다. A/B 테스트에서 사용자가 수락한 제안이 상대적으로 10% 늘었다고 합니다. 10%는 수락률이 10포인트 오른 것이 아니라 기존 수락 건수의 1.1배라는 뜻이니 구분해서 읽어야 합니다. 장점은 제품 실험에서 수락이 늘었다는 점이고, 단점은 상대 10%를 포인트로 오해하기 쉽다는 점입니다. 의미는 앞 장의 설명이 논문과 제품 양쪽에서 뒷받침된다는 것입니다.
