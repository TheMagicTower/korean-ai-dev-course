## A. 용어 먼저, 도구 이름은 그다음
견본: src/periods/p10.html의 ‘개념: LSP와 문서 조회’ 장(새로 추가)과 그 뒤 Context7·Serena 장, p01의 ‘토큰 절약과 MCP’ 장.
- 도구·제품 이름이 **일반 개념보다 먼저** 나오거나, 개념 없이 이름만으로 설명되는 곳을 찾는다.
- 고치는 법: 제목(h2)·tag·노트 첫 문장에서 **정확한 일반 용어**를 먼저 세우고 짧게 정의한 뒤 “대표 도구 X”로 소개한다. 예) “셸 출력 압축 → 대표 도구 rtk”, “정규식 재귀 검색 → ripgrep”, “브라우저 자동화(접근성 트리 스냅샷) → Playwright MCP”, “상한 있는 반복 실행 루프 → Ralph”, “워크트리 기반 병렬 에이전트 관리 → Orca”, “개발 방법론을 스킬 묶음으로 → Superpowers”, “LLM 페르소나 시뮬레이션 → TinyTroupe·UXAgent”, “스펙 주도 개발(SDD) → Spec Kit·Kiro”.
- 서로 다른 개념을 한 범주로 묶지 않는다(예: Context7은 LSP가 아니라 문서 조회).
- 같은 개념을 여러 장에서 다르게 부르면 하나로 맞춘다. 영어 용어는 처음 한 번 “한국어(영어 약어)”로.
- 새 사실(날짜·수치·버전)은 넣지 않는다. 꼭 필요하면 WebSearch/WebFetch로 원문 확인 후에만. 확신 없는 정의는 쓰지 않는다.
- 개념을 세울 새 장이 꼭 필요하면 추가해도 되지만(도식 필수: diagrams/src/*.d2, `node tools/diagrams.mjs NAME`, 견본 p10-lsp-docs.d2), 대부분은 기존 장의 제목·tag·.kind·노트 고치기로 충분하다.

## B. 소개하는 말투
강사는 현업 실무자로서 **소개하러 가는 사람**이다. 가르치고, 지도를 주고, 외우게 하는 말투를 뺀다. 슬라이드 글과 노트(aside) 모두.
- 바꿀 것 예: “오늘의 지도/오늘의 흐름/오늘의 질문” → “오늘 소개할 것/이번 시간 순서/오늘 함께 볼 질문”, “배웁니다/익힌다/학습 목표” → “소개합니다/봅니다/써 봅니다”, “기억하세요/꼭 ~해야 합니다”의 훈계형 → “저는 이렇게 씁니다/이렇게 하면 덜 막힙니다”, “정리하겠습니다”는 “오늘 본 것을 묶으면” 정도로.
- 학생을 시험하는 말, 평가하는 말투를 줄인다. 실습·과제·평가표 자체(과정 구조)는 유지하되 문장은 “해 봅니다/내 주세요” 식으로 부드럽게.
- “금지 시험·일부러 어겨 보기”의 ‘시험’은 테스트라는 뜻이라 그대로 둔다.
- 사실·수치·날짜·장 구성은 바꾸지 않는다.
