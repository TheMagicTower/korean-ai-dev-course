# 자유 하네스·평가 없음 (2026-10-29 11:30 강사 결정)

강사 말:
- “실습에 포함된 자신만의 하네스를 만드는 건 누구나 자신만의 원하는 기능과 스펙을 만드는 하네스를 만드는 실습임. 형태나 구조를 강제할 필요는 없다고 생각함.”
- “그리고 채점이나 평가는 하지 않을 것임.”
(앞선 결정도 유지: 학생은 코드를 읽지 않고 프롬프트와 스모크로 확인 — plan/prompt-smoke-brief.md, 소개하는 말투 — plan/voice-term-brief.md, 설치 안내 없음, 스모크 결과는 예시로 충분)

## 1. 형태·구조를 강제하지 않는다
- 하네스가 **무엇을 하는지(기능·스펙)는 학생이 정한다.** 슬라이드는 “반드시 들어갈 여섯 가지”, “필수 구성”, “코디네이터가 이슈 원장을 읽고 워커에 배치하는 형태”, “이슈 #1 Stop 훅 / #2 테스트 보호 …를 등록하라”, “스킬 하나·MCP 하나·/goal을 반드시” 같은 **정해진 구성 요구를 빼거나 ‘예시’로 바꾼다.**
- 각 실습은 “이번 회차에 소개한 장치들(메뉴) 중 **내 하네스에 필요한 것을 골라** 하네스에게 시킨다”로. 예시 하네스(코디네이터-배치, 딴길 방지 장치 등)는 “이런 식으로도 만들 수 있다”는 **예시**로 남긴다.
- v0~v3 같은 버전 이름은 “회차마다 한 번씩 키운다” 정도로만 쓰고, 버전별 필수 내용은 두지 않는다(써도 ‘예: …’).
- 일하는 방식(질문부터 → 결정 → 승인 → 시키기 → 스모크 → 기록, 18단계·이슈 워크플로우 표시)은 **제가 쓰는 방식으로 소개**하되 강제하지 않는다(“저는 이렇게 합니다. 자기 방식대로 바꿔도 됩니다”).

## 2. 채점·평가 없음
- **배점, 평가 기준, 평가표, 채점, 감점, 점수, 제출 기한, ‘완성도보다 ~를 본다’ 류 평가 문구를 모두 뺀다.** p17의 평가표 장은 없애거나 “발표에서 나누면 좋은 것” 장으로 바꾼다(도식 p17-rubric을 쓰고 있으면 쓰지 않거나 수정).
- “과제 N” 장은 “다음 회차까지 해 볼 것”(또는 “집에서 이어서”)으로: 해 볼 일 2~4줄 + 다음 시간에 **나누면 좋은 것**(쓴 프롬프트, 스모크 표 한 장, 막힌 곳 하나 등). 날짜는 ‘다음 회차(11-12)’처럼 회차 일정으로만.
- 5회차 발표는 **평가가 아니라 공유**: 5분 + 질의 2분 형식, 같은 기준 과제로 돌려 본 결과를 나누는 것은 유지해도 됨(기준 과제는 비교를 위한 공통 과제일 뿐, 점수 없음).
- ‘페르소나 평가’, ‘평가(evals)’ 같은 **기술 용어**는 그대로 둔다(채점과 무관).

## 3. 노트·계획 문서
- 해당 교시의 plan/notes 절에서 배점·평가·제출·감점 언급을 같은 기준으로 고친다. 장을 없애거나 합쳤으면 구간표 장 번호·머리줄 장 수를 맞춘다.
