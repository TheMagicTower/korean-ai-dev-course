**주의 (흔한 오해)**
- auto mode는 “허용 범위를 학습”하는 게 아니라 별도 분류기 모델이 호출마다 판단한다. 안전 보장이 아니라 프롬프트를 줄여 줄 뿐(문서 경고). 한계 수치(놓침 17%, 표본 52건)를 반드시 같이 말한다(7장).
- 분류기를 건너뛰는 것: 허용·거부 규칙, 읽기 전용 도구, 프로젝트 안 파일 편집. 연속 3번/누적 20번 차단 시 사람에게 묻는다. 분류기 모델은 발표 당시 Sonnet 4.6, 현재 문서 기본은 Sonnet 5.
- /loop는 ‘목표 달성까지’가 아니라 ‘정해진 간격 반복’(세션 열려 있을 때만, 7일 후 만료). 목표 달성형은 /goal. 순서: Ralph → 플러그인 → Stop 훅 → /loop → Codex /goal → Claude /goal.
- 1M 인용(MRCR(Multi-Round Co-reference Resolution, 다회차 지시어 해소) v2 78.3%, 압축 15% 감소)은 발표문·한 고객 사례라 일반화 금지(24장). 1M 가격·포함 여부는 모델·요금제별 확인. Codex 창 크기는 단정하지 않는다(23장).
- 비대화형 실행(`claude -p "/goal …"`)은 반복이 끝날 때까지 출력이 안 보일 수 있다(21장).

**예상 질문**
- “auto mode면 아무거나 막힘 없이 되나요?” → 아니오. 기본 차단 목록(운영 배포, 강제 푸시, 보안 테스트 삭제 등)이 있고 놓치는 경우도 있어 격리 브랜치·샌드박스와 함께.

**시연·준비**

**주의 (흔한 오해)**
- 학생이 설정 파일을 쓰거나 읽는 실습이 아니다. 에이전트가 질문하고 ADR·스킬·MCP를 만들며, 학생은 답하고 승인하고 스모크로 확인한다. 승인은 사람만 한다(7장). 슬라이드의 스모크 결과는 모두 예시다.
- 15단계 범위는 격리·충돌·리뷰·머지 규칙이다. PR 생성·머지는 오늘 정하기만 하고 실제는 4회차(16교시)에 한다(6장, 스킬 프롬프트의 ‘PR·머지는 넣지 마’).
- /goal 평가자는 명령 실행·파일 읽기를 못 한다. 증명을 출력에 붙이라고 해야 하고 상한 없으면 비용이 끝없이 늘 수 있다. 자동 승인 모드에서는 도구 승인도 없으니 상한을 꼭 적는다(10장).
- 스킬은 설명 문장이 호출을 좌우한다. 안 불리면 원인을 설명시키고 고친 뒤 같은 문장으로 다시 보게 한다(8·15장).
- MCP는 믿을 서버 하나만, 읽기 위주. 비밀 값은 환경 변수 이름으로만, 설정을 바꾼 뒤엔 새 세션에서 확인(9·15장). 서버가 가져오는 글은 주입 위험이 있어 지시로 따르지 않는지 묻는다.
- 실패한 기록도 좋은 자료이고, 13장 표의 숫자(14분·11턴 등)는 양식용 예시다. 못 쟀으면 못 쟀다고 적는다.

**예상 질문**
- “/goal이 안 끝나요.” → 조건이 모호하거나 측정 불가. 상태를 보고 측정 가능한 문장으로 다시 쓰게 한다(15장).
- “/goal이 없는 도구예요.” → 상한이 있는 반복 실행 루프를 시키고 풀 수 없는 과제로 멈춤을 확인한다(11장).
- “질문이 계속 나와요.” → 8개 안에서 끝내라고 첫 프롬프트에 적었다. 모르는 항목은 선택지 두 개와 장단점 표를 달라고 한다(5장).
- “실패 기록도 나누나요?” → 예. 5회차 발표(공유)의 가장 좋은 소재.

**시연·준비**
- 사전: 지난 회차(8교시) 하네스 저장소와 처리해 둔 이슈 한 건, 4교시 ADR. 프롬프트와 스모크 결과는 슬라이드의 예시로 진행한다(사전 실행 불필요).
- 14장: 제출물 없음. 다음 시간에 나누면 좋은 것만 안내(쓴 프롬프트, 스모크 표 한 장, 막힌 곳 하나). 질문 시간 장 없음 — 설계 대화 중 수시로 받고, 막히면 손들기(15장). 캡처 대기 장 없음.
