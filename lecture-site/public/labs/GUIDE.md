# 도서관 찾기 공통 실습 키트

이 키트는 강남대 AI 소프트웨어 엔지니어링 20시간 과정의 공통 출발점입니다. 개인 아이디어를 탐색 중이거나 설치·API 인증에 막힌 경우에도 같은 사용자 흐름을 실행할 수 있습니다. 게임·서비스·물리 제어 등 개인 주제는 그대로 선택할 수 있습니다.

**파일 선택:** 1회차의 첫 화면과 3회차의 분할 구현에는 `starter.html`을 사용합니다. **2회차 s2-17·25·34는 `module-example.html`을 사용합니다.** 이 파일은 슬라이드와 같은 함수 이름·인자·DOM으로 로드→검색→표시가 연결된 예제입니다. 각 파일의 함수 이름과 인자 형식에 맞춰 실행합니다.

## 회차를 이어가는 방법

개인 프로젝트는 1회차부터 5회차까지 이어집니다. 공통 키트는 같은 조건에서 연습하기 위한 대안입니다. **실습마다 한 경로를 선택**해 해당 결과물을 완성합니다. 키트를 썼다면 결과를 자신의 제품에 어떻게 적용할지 한 줄을 남깁니다.

| 회차 | 공통 경로의 파일 | 이번에 할 일 | 다음에 보존할 것 |
|---|---|---|---|
| 1 | starter.html 또는 나의 단일 HTML | 한 흐름과 세 상태·첫 사용 관찰 | 원본 사본·문제 카드·관찰 |
| 2 | module-example.html → module-work.html | STEP-1 표시 → STEP-2 로드 → STEP-3 연결 | module-work와 입력·실제 결과 |
| 3 | starter.html → s3-work/M.html | 동일한 미구현 TODO에서 A·B 분리·통합 | M / M+A / M+B / M+A+B와 검사 |
| 4 | 3회차 통합 버전 또는 /demo/ | 실패 조건·수정·가상 검사·사람 관찰 | 실행 조건·수정 전후·추가 확인 |
| 5 | 내 제품의 검증한 버전 | 공개·외부 확인·한 문제 개선 | URL·버전·운영 인계 |

2회차 결과물을 보존하고, **로더 연결과 누적 통합이라는 서로 다른 학습 목표**에 맞춰 연습의 기준 파일을 선택합니다. 개인 프로젝트는 이전 결과를 그대로 기준 M으로 삼을 수 있습니다. 스킬 패키지 설치, Jev API 구독, 초파리 시뮬레이터 실행은 선택 심화입니다.

### 실습 시간에는 준비·오류 대응·기록이 포함됩니다

각 실습 슬라이드와 내려받는 지시서에 분 단위 계획이 있습니다. 중간 점검에서 정체되면 한 흐름 또는 안내된 대안으로 전환하고, 마지막 검증·기록 시간을 확보합니다. [전체 시간 운영표](/content/pacing-guide.md)를 함께 봅니다. 수업 중 실습 525분과 휴식 100분을 포함한 전체가 1,200분이며, 주 사이 과제 시간은 별도로 계획합니다.

- 1회차 제작: 시작 10분에 실행 화면이 없으면 starter의 한 흐름만 수정합니다.
- 2회차 로드: 5분에 HTTP 준비가 막히면 내장 JSON으로 같은 경계를 연습합니다. HTTP 실행 여부는 따로 적습니다.
- 3회차 분할: 12분 점검에 두 작업 모두 막히면 A부터 확인하고 B는 제공된 함수와 비교합니다. 복사·재사용을 밝힙니다.
- 5회차 배포: 4회차 과제로 계정 로그인과 공개 파일을 확인합니다. 실습 시작 10분에도 인증에 막히면 공개 데모로 검증을 연습합니다. 확인 범위는 공개 데모 검증 연습이며, 자기 제품은 배포 대기 상태로 기록합니다.

회차 인계 네 줄: **파일·URL과 버전 / 실제 확인한 입력·결과 / 남은 문제 / 다음 첫 행동**입니다. AI에 새 대화를 열 때도 이 기록과 필요한 계약을 전달합니다.

## 1. 가장 빠르게 시작하기

1. `starter.zip`을 내려받아 **압축을 푼 폴더에서 실행합니다**.
2. 폴더 안의 `starter.html`을 Chrome·Edge·Safari 등 브라우저로 엽니다. 브라우저에 파일을 끌어 놓아도 됩니다.
3. 도서관 목록 27개가 보이는지 확인합니다. `포곡` 검색은 1개입니다.
4. 지역을 `기흥구`로 바꾸면, `포곡`과 동시에 일치하는 기록이 없어 0개가 됩니다.
5. 검색어를 지우고 지역을 전체로 바꾸면 27개로 돌아옵니다.
6. 파일을 코드 편집기로 열어 `TODO-1`, `TODO-2`, `TODO-3` 주석을 찾습니다. 수정한 파일을 저장한 뒤 브라우저를 새로고침합니다.

시작 파일은 정상 검색과 지역 필터가 동작합니다. 빈 결과의 초기화 버튼, 후보 저장, 실패 시연은 구현할 부분으로 표시했습니다. TODO 버튼은 구현 대기 상태로 표시됩니다. 코드를 완성한 뒤 직접 확인한 기능과 결과를 제출합니다.

`solution.zip`에는 같은 데이터와 완성 예제 `solution.html`이 들어 있습니다. 먼저 기대 결과와 자신의 시도를 적고, 그다음에 완성 예제와 비교합니다. 완성 예제를 복사한 경우 그대로 표시하고 자신이 변경·설명·검증한 부분을 제출합니다.

각 ZIP에는 다음 네 파일이 들어 있습니다.

```text
starter.html 또는 solution.html  # 데이터와 코드가 내장된 단일 실행 파일
module-example.html             # 2회차의 함수·DOM 계약과 동일한 연결 예제
GUIDE.md                         # 이 안내서
data/libraries.json              # fetch 확장 실습용 실제 데이터와 메타데이터
```

세 HTML 파일에는 실행에 필요한 데이터·JavaScript·CSS가 내장되어 있습니다. 원본 기관 링크를 방문할 때만 인터넷이 필요합니다. 브라우저의 로컬 저장 정책에 따라 `file://`에서 후보 저장이 차단될 수 있으며, 이 경우 화면에 실패를 표시합니다. 검색·필터는 계속 사용할 수 있습니다.

### 2회차의 코드 연결 순서

`module-example.html`을 `module-work.html`이라는 이름으로 복사하고 사본에서 다음 순서로 진행합니다. 원본은 비교용으로 보존합니다. 기본 내장 데이터는 파일을 열어 실행합니다. 필요한 함수와 DOM은 이 HTML에 들어 있으며 원본 파일을 연결 비교 예제로 사용합니다.

1. **s2-17 / STEP-1 표시:** “실제 기록 1개”를 눌러 포곡도서관의 이름·주소·기준일을 확인합니다. “빈 배열 표시”와 “읽기 실패 모킹”을 각각 열어 서로 다른 안내를 확인합니다. HTML의 `STEP-1` 주석 아래 `renderLibraries`를 자신의 화면 문구로 수정합니다. **12분 점검:** 기록 1개와 빈 배열을 각각 표시할 수 있어야 합니다.
2. **s2-25 / STEP-2 로드:** `await loadLibraries()`는 내장 JSON에서 정규화한 27개를 반환합니다. 로컬 HTTP 서버에서는 읽기 방식을 HTTP JSON으로 바꾸고 `./data/libraries.json`을 불러옵니다. **12분 점검:** 27개와 `region: "용인시"`, `district: "처인구"` 등 서로 다른 두 필드를 확인합니다. `./data/missing.json`의 실제 404를 확인한 뒤 정상 경로로 되돌립니다.
3. **s2-34 / STEP-3 연결:** “전체 연결로 돌아오기”를 누른 뒤 검색 입력과 지역 변경이 `update`를 거쳐 결과에 반영되는지 봅니다. STEP-3에서 `function update()` 하나만 교체합니다. `libraryRows`, `loadAndRender`, `resetLibraryFilters`와 기존 이벤트 연결을 한 번씩 유지합니다. **15분 점검:** 공백 27개, 포곡 1개, 기흥구 9개, 포곡+기흥구 0개, 초기화 27개를 확인합니다.

슬라이드와 같은 콘솔 예시는 이 파일에서 그대로 실행합니다.

```js
const rows = await loadLibraries();
renderLibraries(rows.slice(0, 1));
renderLibraries([]);
renderLibraries(searchLibraries(rows, { q: ' 포곡 ' }));
console.assert(searchLibraries(rows, { district: '기흥구' }).length === 9);
```

`module-example.html`의 DOM은 `#library-query`, `#library-district`, `#library-results`, `#result-count`입니다. 전체 지역 값은 빈 문자열 `''`입니다. `searchLibraries(rows, {q, district})`의 두 번째 인자는 객체입니다. 3회차 `starter.html`의 `LibraryLab.searchLibraries(rows, query, district, ...)`는 위치 인자를 사용합니다. 각 파일의 호출 형식에 맞춰 작성합니다.

## 2. 이 데이터가 말해 주는 범위

| 항목 | 이 키트의 값 |
|---|---|
| 원본 | [공공데이터포털 전국도서관표준데이터](https://www.data.go.kr/data/15013109/standard.do) |
| 제공기관 | 경기도 용인시 |
| 추출 범위 | 경기도·용인시 기록 27개 |
| 기록 기준일 | 2024-11-20 |
| 수집일 | 2026-10-22 |
| 지역 파생 값 | 주소의 기흥구·수지구·처인구를 추출합니다. 원본 `region`은 용인시입니다. |
| 이용 조건 | 해당 제공기관 상세정보에서 이용허락범위 제한 없음을 확인했습니다. 다른 데이터셋은 각 공식 상세정보에서 조건을 확인합니다. |

원본 값과 원본 필드명 대응은 `data/libraries.json`의 `metadata`에 있습니다. 원본 홈페이지 주소와 운영시각을 보존했습니다. 추출 범위는 이번 다운로드에 포함된 용인시 27개 기록입니다.

**총 좌석 수는 기록 기준일의 좌석 규모입니다.** 수집일은 다운로드한 날이고, 행별 기준일은 원본 현황의 기준 날짜입니다. 실시간 잔여 좌석은 추가 확인 항목입니다. 개관 여부·접근성은 방문 전에 [용인시 도서관 공식 홈페이지](https://lib.yongin.go.kr/)의 운영 안내에서 확인합니다.

### TODO-2: 후보 저장과 실패 처리

- `restoreSaved`는 저장된 JSON을 읽고 올바른 목록인지 검사합니다. 알 수 없는 ID는 제외합니다.
- `commitSaved`는 이전 `Set`을 직접 바꾸지 않고 새 후보 목록을 만듭니다.
- `localStorage.setItem`이 성공한 다음에만 `{ok:true,saved:새로운Set}`을 반환합니다.
- 저장이 차단되거나 `forceError`가 참이면 `{ok:false,saved:이전Set,message:안내}`를 반환합니다.
- 구현 후 `FEATURES.save`를 `true`로 바꾸고 저장·해제·새로고침·저장 실패 모킹을 확인합니다.

저장 성공 후 “저장됨”으로 표시하고, 실패 후에는 이전 후보 수와 표시가 유지되는지 확인합니다. 후보 목록은 현재 브라우저에 저장합니다. 과제 제출은 강의 홈페이지의 해당 회차에서 별도로 진행합니다.

## 4. 로컬 서버와 fetch로 확장하기

단일 HTML의 기본 실행은 JSON을 파일 안에서 읽습니다. `fetch`를 배우려면 압축을 푼 폴더에서 터미널을 열고 다음 중 사용 가능한 명령을 실행합니다.

macOS·Linux:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Windows:

```powershell
py -m http.server 8080 --bind 127.0.0.1
```

브라우저에서 2회차에는 `http://localhost:8080/module-work.html`, 3회차에는 `http://localhost:8080/starter.html`을 엽니다. 사본을 아직 만들지 않았다면 `module-example.html`로 기준 실행을 확인합니다. 끝나면 터미널에서 `Ctrl+C`로 서버를 종료합니다. 포트가 이미 사용 중이면 8081 등으로 바꾸고 주소도 함께 바꿉니다.

Python 준비에 막히면 내장 데이터 버전으로 실습을 계속합니다. 강의 홈페이지의 `/demo/`와 `/data/libraries.json`을 활용할 수도 있습니다. 기록 유형은 직접 실행 또는 공개 화면 관찰로 표시합니다.

**로컬 HTTP 주소의 `module-example.html`**에서 개발자 도구 콘솔에 다음 코드를 입력합니다.

```js
const httpRows = await loadLibraries('./data/libraries.json');
console.log(httpRows.length); // 27
console.log(searchLibraries(httpRows, { district: '기흥구' }).length); // 9
renderLibraries(httpRows);
```

화면의 “데이터 읽기 방식”을 HTTP JSON으로 바꾸고 “자료 불러오기”를 누르면 입력 이벤트까지 연결된 로더를 사용합니다. HTML의 `STEP-2`와 `STEP-3`를 읽고 로드 성공·실패·입력 이벤트의 순서를 설명합니다. 콘솔에서 렌더러만 직접 호출한 상태와 전체 입력 연결 상태를 구분합니다.

공개 강의 사이트와 ZIP을 푼 로컬 폴더 모두 **`./data/libraries.json`** 경로를 사용합니다. 공개 사이트의 `/labs/data/libraries.json`은 원본 스냅샷을 그대로 복사한 파일입니다. 전체 강의 데이터의 `/data/libraries.json`도 같은 내용입니다.

`file://`에서 별도 JSON을 `fetch`하면 브라우저 보안 정책 때문에 차단될 수 있습니다. 이는 검색 함수 오류나 포털 장애와 다릅니다. 브라우저 보안 설정을 유지하고 내장 데이터 방식 또는 로컬 HTTP 서버를 사용합니다.

404와 빈 결과를 구분하려면 HTTP 주소에서 파일명을 `./data/missing.json`으로 바꿔 요청합니다. 응답이 404인지 확인한 뒤 `libraries.json`으로 되돌립니다. 기본 실습은 공개 스냅샷으로 실행합니다. 원격 공공데이터 API 연결은 이용신청·본인 인증키·허용 범위를 확인한 뒤 확장합니다.

### 3회차: Git 없이 통합 후보를 보관하는 순서

1. `s3-work/` 폴더에 변경 전 `starter.html`을 `M.html`로 복사하여 보존합니다.
2. `M.html`을 `M+A.html`과 `M+B.html`로 각각 복사합니다. A는 TODO-1 초기화만, B는 TODO-2 저장·복원만 수정하고 각 후보를 검사합니다.
3. 검사한 `M+A.html`을 `M+A+B.html`로 복사합니다. `M+B.html`의 `restoreSaved`, `commitSaved`, `FEATURES.save` 변경만 옮깁니다. 각 함수의 변경 범위를 확인해 옮깁니다.

검사 기록 한 행의 예시 형식은 다음과 같습니다. 실제 결과는 실행한 뒤 관찰한 값으로 채웁니다.

기대=저장1개유지·전체27개복귀 | 실제=직접 실행 후 작성 | 근거=화면 파일명·실행 시각

### 4회차 과제: 5회차 배포 준비를 먼저 끝냅니다

5회차 30분 공개 실습은 배포·외부 확인·기록에 배정합니다. **4회차가 끝난 뒤** 설치와 계정 가입을 준비하고, 막힌 항목을 강사에게 알립니다.

- 자신의 컴퓨터에서 `node --version`, `npm --version`이 실행되는지 확인합니다. 강의 개발 환경은 Node.js 22 이상을 사용합니다.
- 자신의 Cloudflare 계정에 로그인할 수 있고 해당 프로젝트를 만들 권한이 있는지 확인합니다. 설정은 본인 계정의 새 실습 프로젝트를 기준으로 작성합니다.
- 새로운 실습 배포 폴더에서 `npm install --save-dev wrangler`를 실행하고 `npx wrangler login`으로 인증을 마칩니다. 비밀번호·토큰은 본인의 로컬 인증 도구에서 관리합니다.
- 2회차 연결 예제 또는 자신이 수정한 시작 파일을 로컬에서 실행하고, 공개할 핵심 흐름 하나를 정합니다.
- 설치·가입·인증이 막혔다면 수업 시작 전에 대안을 정합니다. 5회차에는 공개 데모에서 검증 활동을 수행하고 자신의 제품은 배포 준비 상태로 정확히 기록할 수 있습니다.

### 5회차: HTML 실습 폴더를 배포 폴더로 옮깁니다

원래 작업 파일을 보존하고 새 폴더를 만듭니다. 파일 탐색기에서 다음 구조로 복사하면 운영체제별 복사 명령을 몰라도 진행할 수 있습니다.

```text
my-course-product/
  wrangler.jsonc
  package.json             # Wrangler를 설치하면 생성/갱신됩니다.
  package-lock.json
  public/
    index.html             # 수정한 starter.html 또는 module-example.html을 복사해 이름 변경
    data/
      libraries.json       # ZIP의 data/libraries.json을 그대로 복사
```

내장 JSON 버전도 `data` 폴더를 함께 보관하면 HTTP 확장을 이어갈 수 있습니다. `module-example.html`을 `public/index.html`로 옮기면 기본 HTTP 경로는 `./data/libraries.json`이며 공개 루트의 `data` 폴더와 일치합니다. 이름을 바꾼 뒤 `public/index.html`을 열어 복사한 파일이 맞는지 먼저 확인합니다.

`wrangler.jsonc`는 `public` 폴더 **옆**에 저장합니다. `name`은 자신의 프로젝트 이름으로 바꿉니다.

```json
{
  "name": "make-good-my-team",
  "compatibility_date": "2026-10-23",
  "workers_dev": true,
  "assets": { "directory": "./public" }
}
```

준비한 `my-course-product` 폴더에서 실행합니다.

```sh
npx wrangler dev --port 8787
# 브라우저에서 http://localhost:8787 을 확인한 뒤 Ctrl+C로 종료합니다.
npx wrangler deploy
```

반환된 공개 주소를 새 브라우저 상태에서 열고 같은 스모크 흐름을 실행합니다. URL·배포 버전·실행 시각·관찰한 결과를 함께 기록합니다. 기존 서버/API 프로젝트는 해당 프로젝트의 배포 방법을 따릅니다. 강의 홈페이지의 Worker·DB·강사 인증 정보는 수업 운영 전용이며 학생은 본인 실습 환경을 사용합니다.

실행표의 예시는 다음과 같습니다. “실제 결과” 칸은 자신의 실행 후 채웁니다.

| 검사 | 시작·입력 | 기대 결과 | 실제 결과·근거 |
|---|---|---|---|
| 정상 | 검색어 `포곡`, 전체 지역 | 1개 | 직접 실행 후 작성 |
| 지역 | 검색어 없음, 기흥구 | 9개 | 직접 실행 후 작성 |
| 경계 | 검색어 공백 3개 | 27개 | 직접 실행 후 작성 |
| 빈 결과 | 포곡 + 기흥구 | 0개, 복귀 행동 제공 | 직접 실행 후 작성 |
| 상태 | 후보 1개 저장 후 다시 열기 | 같은 후보가 저장됨 | 환경·브라우저를 함께 작성 |
| 읽기 실패 | 실패 버튼을 켬 | 모킹 오류 안내, 재시도 후 기존 조건 | 모킹·학생 직접 조작으로 표시 |
| 저장 실패 | 저장 실패 모킹 후 다른 후보 저장 | 실패 안내, 기존 후보 유지 | 모킹·학생 직접 조작으로 표시 |

## 6. 개인 프로젝트로 바꾸기

도서관 찾기는 공통 연습 재료입니다. 개인 프로젝트에서는 다음 대응만 먼저 정합니다.

- 도서관 목록 → 내 사용자가 판단할 실제 대상이나 게임 자원
- 이름·지역 검색 → 사용자가 목표를 달성하는 핵심 입력
- 후보 저장 → 사용자의 결정을 유지해야 하는 상태
- 읽기·저장 실패 → 내 제품에서 실제로 생길 수 있는 실패
- 출처·기준일 → 내 결과를 믿을 수 있는 범위와 확인 방법

물리 제어를 선택했다면 실제 장치 연결 여부, 명령 승인, 실행 결과 확인과 안전한 중단을 별도로 정의합니다. 장치 실행 결과는 실제 응답과 움직임을 관찰해 별도로 기록합니다. 공통 키트는 화면 시뮬레이터 범위로 사용합니다.

주제는 세상을 긍정적으로 바꿀 수 있어야 합니다. 예상 효과는 아이디어이며 사용자에게서 실제로 확인한 변화와 구분합니다. 공공데이터를 활용한다면 필요한 필드가 있는지 확인한 뒤 화면에서 약속합니다.

## 7. 가상 사용자와 모킹을 기록하는 법

예시 가상 사용자: “수업 사이 40분이 남은 학생이 기흥구의 도서관 후보 한 곳을 저장하려고 합니다. 모바일 화면을 사용하고 처음 방문했습니다.” 자료 성격: 강의용 가상 사용자 가정입니다.

목표·초기 상태·행동·성공 조건을 먼저 적고 실행합니다. `실제 공개데이터`, `학생이 직접 실행`, `AI 가상 사용자`, `실패 모킹`, `실제 사용자 관찰` 중 어떤 근거인지 표시합니다. 실패 모킹의 확인 범위는 지정한 조건에서의 오류 안내·복구 동작입니다. API 안정성과 사용자 만족도는 각각 운영 기록과 실제 사용자 관찰로 확인합니다.

## 8. 빠르게 끝낸 학생의 심화 과제

1. `LibraryLab.searchLibraries`의 검색·지역·저장 후보 조건을 자동 검사합니다. “포곡+기흥구는 0개”처럼 서로 다른 조건이 함께 적용되는 사례를 포함합니다.
2. 저장이 차단된 저장소를 주입하고 이전 후보 Set이 유지되는지 확인합니다. 성공·실패 조건을 함께 검사합니다.
3. 잘못된 JSON·알 수 없는 후보 ID·같은 이름의 시설·빈 목록을 준비하고 실패 원인과 안내를 구분합니다.
4. 별도 브라우저 환경에서 키보드만으로 검색→저장→0개→복귀를 실행합니다. 함수 검사와 화면 검사를 구분합니다.
5. 실제 사용자에게 버튼 이름 없이 목표만 전달하고 관찰합니다. 개인정보를 수집하지 말고 동의를 받은 범위에서 행동과 도움 요청을 기록합니다.
