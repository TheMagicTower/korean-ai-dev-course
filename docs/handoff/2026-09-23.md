## 목표와 작업 원칙

목표는 한국어 AI 개발 스킬과 운영 체계를 정리하고, 학생이 자신의 아이디어 하나를 4주(주 1회 2시간) 동안 완성하도록 돕는 강의 자료와 실행 사례를 제공하는 것입니다. 구현·사례 설명은 프로젝트를 끝까지 만들고 검증·전달하는 데 집중합니다.

사용자가 직접 정한 중요한 선택은 다음과 같습니다.

- 수강생은 각자 아이디어 하나를 고르고 같은 프로젝트를 네 주간 이어서 만듭니다. 공통 완성 기준을 적용하며 세 사례 모두를 과제로 만들지 않습니다.
- 사용 경험 시안을 문서화와 상세 작업 분해 사이에 둡니다. 목업을 먼저 다뤄 규칙·API·DB를 도출하며, DB 설계부터 시작하던 순서와 대비합니다.
- 개인·PoC·MVP·운영 서비스의 완료 기준과 위험·예산을 구분합니다. 개인 프로젝트에 기업 운영 절차를 일괄 강제하지 않습니다.
- 사용자는 통상 약 6배 빨라졌다고 경험했지만 이는 통제 실험으로 입증된 수치가 아닙니다. 실제 시간·비용·검증 범위는 증거와 함께 구분합니다. 교재에는 GPT-6 Astra·Jev와 GPT/Claude/Grok/GLM 프로바이더 관점, Claude Code·Grok Build·OnDemand·Codex·Pi·Oh My Pi·OpenCode·Replit 조사 부록이 있습니다. 변동 정보는 적용 시 공식 출처를 다시 확인합니다.
- 단순한 작업에는 GPT-5.6 Luna Max 서브에이전트를 선호하고, 작업 분류에는 Jev를 사용합니다. Jev 호출은 현재 계정 환경의 `TYPESAFE_API_KEY`를 사용하되 값이나 인증 내용을 로그·문서에 남기지 않습니다.
- 한국어 존댓말을 사용합니다. 다음 세션은 인계 문서만 믿지 말고 실제 Git·파일·실행 상태를 확인합니다.

## 새 세션 시작 절차

저장소 루트에서 먼저 다음을 실행하고 결과를 이 기준과 비교합니다.

```sh
git status --short --branch
git fetch origin
git log -5 --oneline --decorate
git rev-parse HEAD origin/main
git worktree list
gh pr list --state open
gh run list --branch main --limit 5
```

새 세션에서 기준 SHA와 다르면 현재 공개된 커밋을 기준으로 인계 내용을 갱신합니다. 로컬 변경이 있으면 보존 여부부터 판단하고 덮어쓰지 않습니다. 변경이 필요하면 `codex/` 접두어의 작업 브랜치에서 진행하고, 필요한 CI·공개 배포를 확인한 뒤 핸드오프를 최신화합니다.
