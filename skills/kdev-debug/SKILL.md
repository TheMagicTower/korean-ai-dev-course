# 오류 진단

한국어 존댓말로 설명하며 코드·API 식별자는 원문을 유지합니다.

## 적용 범위와 비용

사용자의 명시적 요청과 기존 프로젝트 규칙을 먼저 따릅니다. 사용 범위(개인·팀·외부), 목표 단계(PoC·MVP·운영), 실제 위험, 이번 작업 예산과 완료 조건을 기존 계약에서 읽습니다. 없으면 작업에 영향을 주는 부분만 확인하거나 가정을 표시합니다. 저위험 개인 작업에 기업용 문서·로그인·CI/CD·독립 리뷰를 일괄 추가하지 않습니다. 필요한 조건을 통과하면 종료하고 선택 개선은 후속으로 남깁니다. 예산 소진 시 필수 미달은 미완료로 인계합니다. 없는 도구·권한·실행 증거를 가정하지 않습니다.

## 수행

1. 기대 결과·실제 결과·환경·버전·재현 입력을 확보합니다. 민감정보는 제거합니다. 재현되지 않으면 재현 불가와 필요한 증거를 명시합니다.
2. 증상과 원인을 구분하고 관련 코드·로그·계약에서 가장 작은 가설을 검증합니다. 환경·권한·계정·배포 버전 문제를 모델 성능 문제로 섣불리 바꾸지 않습니다.
3. 같은 실패를 두 번 반복하면 다음 시도 전 새 증거·가설·입력·환경 중 무엇을 바꾸는지 정리합니다. 반복 횟수는 프로젝트 정책이 있으면 따릅니다.
4. 진단만 요청받았으면 원인·근거·수정안을 제시하고 코드는 바꾸지 않습니다. 수정 요청 범위에서는 최소 원인 수정을 하고 원래 실패와 관련 회귀를 확인합니다.
5. 피드백 이슈에 재현·영향·근거·판정·다음 작업을 남깁니다. 이슈 등록은 요청된 경우 수행하고 아니면 초안을 제공합니다.
6. 자동 처리 반려·예산 소진·고복잡도·사용자 ADR 판단이 필요하면 시도한 내용과 필요한 결정·재개 조건을 인계합니다. 이 스킬은 스케줄러 자체를 설치하거나 새 스케줄을 만들지 않습니다.

## 산출물과 종료

재현 → 증거 → 원인 또는 미확인 가설 → 수정 → 재검증 순서로 보고합니다. 원인을 고치지 못했다면 해결했다고 표시하지 않습니다. 새 증거 없이 리뷰·전체 구현을 반복하지 않습니다.
